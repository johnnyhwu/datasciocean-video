# 01 使用者的要求、原話與評語

給接手的 Claude：這份是「做給誰看、他要什麼」。**技術再好，方向錯了就沒用，先讀這份。**

## 一、使用者是誰、做什麼

- DataSci Ocean（datasciocean.com）的作者，用**繁體中文**寫 AI 論文解析。
- 文章被提煉成「觀念卡」，放在 `datasciocean-concept-wiki` repo 的 `wiki/concepts/*.md`。
- 這兩次實驗的目標：從觀念卡做出 **YouTube 解說影片**，風格像 3Blue1Brown，但更活潑。
- 和使用者溝通一律用**繁體中文**。

## 三、從原話歸納出的偏好（依重要性）

1. **動畫本身要把技術細節講清楚。** 使用者說這是「最重要的」。
   - 不是旁白講、畫面配圖，而是**看畫面就懂機制**：數字怎麼來、哪一步丟了什麼、為什麼這樣設計。
2. **有趣、有創意、敢誇張。** 誇張是為了讓人想看下去，例如：
   - 油壓機壓扁機率、蓋「平手！」印章、會說話的機器人評審、倒帶、魚鉤撈表。
   - 但誇張必須服務於講清楚，不能只是裝飾。
3. **讓觀眾想看完。** 開場要有鉤子；要有角色；伏筆要回收；章節要清楚；畫面不能長時間不動。
4. **觀念細節不含糊。** 限定條件、反直覺的地方、論文沒說的地方都要講。
5. **自主完成、自己檢查。** 使用者中途會離開：
   - 產出前不要停下來問，不要放棄；
   - 產出後自己找問題、修掉，再交付。
6. **片長由 Claude 決定。** 兩版都約 10 分鐘，使用者沒有抱怨長度。重點是節奏，不是秒數。

## 五、長期規則（這個使用者的環境，一定要遵守）

- **不要自己 commit 或 push**，時機由使用者決定。
- **不要安裝任何東西到全域。** 一律用 `uv` 管專案內的環境（`uv run python ...`），不要 `pip install`。
- **觀念卡 repo 是唯讀的。** 不修改卡。
- **影片內容只能來自觀念卡。** 只用 `status: normal` 的主張，`pending_author_confirmation` 的不用。
  - 主張的 `qualifiers`（限定條件）要跟著講。
  - 自己補的數字要標「示意」。
- **花錢前先講預估成本。** 例如要用付費 TTS API 時，先說清楚、等使用者同意。這兩版都沒有花錢，全部離線。
- **不要讀或印出 `.env`、不要向使用者要 token。**
- **快照資料夾（final_high、final_xhigh）不要覆蓋**，包含裡面的文件。新版本放新資料夾。
- **聲音沒經過人耳確認的部分要明講。** Claude 聽不到，這是事實，不要假裝確認過。
- 不要在 repo 的成品裡寫模型名稱（例如 commit message、程式註解）。
