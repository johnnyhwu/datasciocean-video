# 04 錯誤與教訓：遇過的坑、原因、怎麼避免

格式：**症狀 → 原因 → 解法或避免方式**。標記 [11.1] 表示早期選工具的實驗，[v3] 表示 final_high，[v4] 表示 final_xhigh。

**最重要的一條：Claude 看不到畫面、聽不到聲音。** 幾乎所有問題都是靠下面三種方式之一抓到的：

1. 程式檢查：版面、靜止段落、同步、響度；
2. 看縮圖；
3. 讀語音辨識的回轉結果。

**每次產出都要跑，省不得。**

---

## 一、環境與網路

| 症狀 | 原因 | 解法 |
|---|---|---|
| HuggingFace、Bing 語音、OpenRouter 連不上 [v3] | 這個雲端容器的網路政策只放行 PyPI、npm、GitHub release | 模型一律從 **GitHub release** 下載。Kokoro ONNX 在 `thewh1teagle/kokoro-onnx` 的 release，SenseVoice 在 `k2-fsa/sherpa-onnx` 的 `asr-models` release。先用 `curl -o /dev/null -w "%{http_code}"` 測通不通 |
| 沒有 LaTeX，`MathTex`、`DecimalNumber`、`Axes` 的數字標籤都會失敗 [v3] | 容器沒裝 TeX，而且不能裝到全域 | 數字用 Text 做的計數器 `num()`（`ValueTracker`＋`always_redraw`），圖表自己畫（`Chart`）。公式用文字排，例如「0.02 + 0.10 + … = 4.16」 |
| 中文字缺字或字型不對 | Manim 的 Text 走 Pango，需要系統找得到字型 | 把 Noto Sans CJK TC（OFL 授權）放進 `~/.fonts/`，Text 指定 `font="Noto Sans CJK TC"`。ffmpeg 燒字幕要給 `fontsdir` |
| 環境有 GCP 憑證，但我刻意沒用雲端 TTS [v3] | 付費 API 要先跟使用者講成本、等同意，而使用者中途不在 | 全部用離線模型。未來要用付費 TTS，先估成本並等使用者明確同意 |
| `rsync` 不存在 [v3] | 容器沒裝 | 用 `tar -cf - … | tar -xf -` 複製，排除項目用 `--exclude` |
| Bash 的前景 `sleep` 被擋 [v4] | 執行環境的規則 | 長時間工作用背景執行（`run_in_background`）。等待用 `until grep -q 完成標記 log; do sleep 10; done`，並放在背景執行 |

## 二、TTS（Kokoro v1.1-zh＋misaki G2P）

| 症狀 | 原因 | 解法 |
|---|---|---|
| 多音字念錯：重複、重疊念成 zhòng；量表念成 liáng；量一百次念成 liàng；乾淨念成 qián [v3] | misaki 的中文 G2P 依詞切分，常常選錯讀音 | 寫腳本後跑 `tts/poly.py`，列出所有含多音字的詞和注音，逐一看。錯的在 `synth.py` 的 `prep()` 換成同音字，例如「重複→蟲複」「量表→亮表」「乾淨→干淨」 |
| v4 新發現的錯讀 [v4] | 同上 | 「要重跑→要蟲跑」「量越多次→梁越多次」「誤差→誤插」「只在乎→止在乎」「推敲得出來→推敲的出來」「對應→對映」「處理→楚理」「挑中→挑眾」 |
| 「得」念成 de，但意思是 děi（必須）[v3, v4] | 判斷不出語意 | **改寫句子**，不用 děi 的「得」：「都得表態→都必須表態」「成本就得重算→成本就要重算」 |
| jieba 切詞把「差」切進下一個詞，讀音跟著變 [v4] | 例如「誤差範圍」被切成「誤／差範」 | 用整個詞去替換，不要只換單字 |
| 英文單字沒有音標，程式停下來 [v3] | `en()` 只認字母縮寫和 `WORDS` 表裡的字 | 在 `WORDS` 加音標，例如 argmax、pivot、token、terminal、bench、ensemble。連字號的詞（Terminal-Bench）要在 `say` 改成空白分開 |
| 數字和英文黏在一起念不清 [v3] | 例如「20」和「77」連在一起 | 給 `say` 另外寫念法，加逗號斷開，例如「換成一到二十。這次，有七十七次排對」 |
| 語音辨識字錯率高，但其實念對了 [v3, v4] | SenseVoice 對英文和同音字辨識不準（argmax→阿瑪、尺→齒、pivot→佩文） | 只把字錯率當**篩選**用：超過 0.12 的逐條看，確認是同音字才放過 |
| 片長失控：v4 第一稿合成出 11.7 分鐘 [v4] | 句子太多，每句太長 | 合成後先算總長（語音＋間隔＋停頓＋章節卡留白），超過目標就回頭刪句子、合句。語速可以從 1.10 調到 1.15，但不要更快 |
| Kokoro 中文聲音偏平 [v3, v4] | 模型本身的限制 | 加第二個說話者（機器人）製造對話感；用 `hold` 控制句間停頓。**沒經人耳確認要講明** |

## 三、Manim（ManimCE 0.22）

| 症狀 | 原因 | 解法 |
|---|---|---|
| 機器人整隻被染成同一色 [v3] | VGroup 子類別設了 `self.color`，和 Manim 的屬性衝突 | 自訂屬性改名，例如 `self.tint`。不要用 `color`、`width`、`height` 這類 Manim 已用的名字 |
| 嘴型變形後留在原地，跟不上縮放的頭 [v3] | 同一次 `play` 同時對父物件和子物件下 `.animate` | 分成兩個 `at()` 呼叫，或者改用 updater |
| 長條的百分比標籤在群組移動後錯位 [v3] | 標籤沒加進同一個群組 | 加進群組，或在移動後呼叫 `place_labels()` |
| 落下的積木殘留在畫面上 [v4] | `self.remove(VGroup)` 不會移除被個別動畫加進場景的子物件 | 用 `self.remove(*group)` |
| 3×8 小格裡的直方圖消失 [v4] | 對子物件呼叫 `cell[0].animate…` 時，它被提到最上層，把同組的直方圖蓋住 | 對整組用 `Indicate(cell)`，不要對子物件下 `.animate` |
| `TypeError: Animation only works on Mobjects` [v4] | 把 list 傳給 `FadeIn`，例如 `FadeIn(tm.submobjects[:3])` | 包成 `VGroup(*list)` |
| 平行渲染時出現 `FileNotFoundError: media/texts/xxx.svg` [v4] | 同一個 .py 的多個場景同時跑，互搶 Text 的 SVG 快取 | **每個場景用自己的 `--media_dir media/<場景>`**。`v4/render.sh` 已經這樣做 |
| 在 manim 環境 `import soundfile` 失敗 [v4] | 兩個 uv 環境是分開的，soundfile 只在 TTS 環境 | 在動畫程式裡用標準庫的 `wave` 讀 wav |
| 版面檢查誤報：物件已經滑出畫面，仍被判定越界 [v4] | 甩鏡時物件被移到畫面外 | 檢查時跳過完全在畫面外的物件（`b[2] < 0 or b[0] > 1`）。要藏起來的東西用 `FadeOut`，不要只是移到邊緣（v4 的機器人往下移 4 單位，還露出一截在字幕區） |
| `set_line_spacing` 出現棄用警告 [v4] | API 變了 | 多行文字用 `VGroup(*[Text(...)]).arrange(DOWN)` |
| 改寫腳本後渲染報 `StopIteration` 或 KeyError [v4] | 句子 id 重新編號，舊的 `A("a11")` 錨點找不到 | 改腳本後先 grep 所有 `self.A("…")` 用到的 id，再對照 script.json。從最大的編號往回改，避免連鎖替換 |

## 四、版面與畫面（看縮圖才抓到的）

| 症狀 | 解法 |
|---|---|
| 元素太小、畫面大片空白，像投影片 [v3→v4 改善] | 字級至少 0.03 的畫面高度，重點數字 0.06～0.14。元件要把主畫面區（上方 74%）用滿 |
| 左上角的大標題和後面出現的圖表撞在一起 [v4] | 圖表出現時把大標題淡出，只留章節小標或旋鈕圖示 |
| 標籤和數字疊在一起，例如「+16.6」壓到 70.8%、「其他條件都沒變」超出右邊界 [v4] | 先算右邊界（`XR`），超過就換到左邊或下方。放置時用 `next_to`，並在之後檢查 `get_right()` |
| 開關上的字和身體同色，完全看不見 [v4] | 橘色身體配橘色字。改成「啟用的白字、未啟用的深色半透明」 |
| 示意位置選錯，兩個看法落進第 5 格而不是第 4 格 [v4] | 0.80 剛好在第 4、5 格的邊界上。示意數字要避開邊界，並先手算落點 |
| 動畫會誤導：開關切到期望值又馬上切回 argmax [v4] | 每個動作都要對應旁白的意思。開關改在期望值長條長出來時才切 |
| 有「示意」內容但沒標 [v4] | 終端機指令、體重計讀數、尺的讀數、評審漏看的紀錄，事後才補上標籤。**寫腳本時就列出所有示意內容** |
| 字幕區被畫面元素侵入 [v3] | 主畫面只用上方 74%，74%～80% 放註解，80%～95% 是字幕。程式每格檢查 |

## 五、時間同步

| 症狀 | 原因 | 解法 |
|---|---|---|
| `animation at X starts late` [v3, v4] | `at()` 是依序播放，前一個動畫太長就會擠到下一個 | 長動畫要確認不會吃到下一句。例如收尾的晃動從 1.6 秒縮成 0.75 秒；紙屑和片尾卡改成錯開 1.35 秒。晚 0.1～0.4 秒可以接受，超過 0.5 秒要修 |
| 動畫開始得比旁白早或晚 [v3] | 錨點比例估錯 | 用 `A(id, frac)` 掛在「旁白念到那個詞」的比例。重要的字可以用字數比例估算 |
| 章節卡沒有時間 [v4] | 章節卡需要沒有旁白的空檔 | 在腳本裡給該場 `pad: [1.7, …]`，前一場結尾留約 1.3 秒，由 `finish()` 自動蓋上章節卡 |

## 六、聲音

| 症狀 | 原因 | 解法 |
|---|---|---|
| SFX 合成時 numpy broadcast 錯誤 [v3] | 兩段長度不同的陣列直接相加 | 用 `add(*xs)`，先補到同長度再相加 |
| 各種音效響度不一 [v4] | 原本以峰值正規化 | 以「有聲部分 RMS」逐種校正，再乘上每種音效的修正值（`TRIM`） |
| 背景音樂蓋過人聲的風險 [v4] | — | 量化檢查：旁白期間音樂比人聲低約 20 dB，在 1～4 kHz 語音頻段低約 24 dB。另交付一版無音樂版 |
| 單段響度正規化有誤差，v3 量到 −16.9 LUFS [v3] | ffmpeg `loudnorm` 單段動態模式 | v4 改成兩段式：先量測，再套 `measured_*`＋`linear=true`。結果 −16.4 LUFS |

## 七、流程與工作習慣

| 錯誤 | 教訓 |
|---|---|
| **v4 誤把更新後的手冊複製進 `final_high/PLAYBOOK.md`**，覆蓋了快照 | 快照絕對不動。要更新共用文件，只寫到 `experiments/`。事後用對話開頭讀到的原文還原，並用 `CHECKSUMS.txt` 確認成片沒動 |
| 一次寫太多場景才渲染，錯誤一起爆出來 [v4] | 每寫好 2～3 場就低畫質（`-ql`）渲染加縮圖檢查。一輪修完再用 1080p 渲染 |
| 用 1080p 才發現問題，重渲很花時間 [v4] | 先低畫質修到滿意；1080p 只重渲改過的場景（`SCENES="s2:Sc04" Q=h ./render.sh`） |
| 第一版縮圖問題很多，例如 sc02 的機率表太小、sc03 積木殘留、sc01 百格圖只亮 27 格 | 正常現象，**一定要看縮圖**。每場結束畫面拼成一張圖（`sheet.py`），一次看一場 |
| 長時間沒向使用者回報 | 使用者會收到「很久沒消息」的提醒。每個階段用一兩句說明正在做什麼 |
| 靜止偵測的閾值太敏感 [v4] | 細線或小字在動時，平均像素差很小，會被判成靜止。看清楚是不是真的不動，再決定要不要補 |

## 八、早期選工具時的教訓 [11.1、11.1b]（為什麼最後用 ManimCE）

完整內容見 `docs/background/11.1b-transformer-four-tools.md`。

- 四種工具都做得出來：ManimCE、HTML＋GSAP＋Playwright、HyperFrames、Remotion。**工具不是瓶頸，Claude 看不到畫面才是。**
- **ManimCE 最省 token、渲染最快，而且逐格可重現**（同樣輸入，每一格像素都一樣）。網頁路線最大的隱性成本是「跳到任意時間，畫面要一樣」。GSAP 有 4 個陷阱：
  - SVG 的透明度被 CSS 和屬性同時控制；
  - 座標會被自動取整數；
  - 文字的 transform 影響反鋸齒；
  - "0.10" 被當成數字，顯示成 0.1。
- HyperFrames 的內建 `check` 會抓可讀性問題，例如文字停留太短、字小於 28 px。這是自己寫的檢查沒有的，值得把類似檢查移植到 Manim 流程。
- Remotion 要寫 React、依賴 476 MB，而且有授權條件，不推薦。
