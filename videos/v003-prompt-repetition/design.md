# v003 設計紀錄：一條只能回頭看的長廊

## 一張大圖

機制的形狀是「一排字由左往右讀，每個字只能回頭看」。所以大圖是一條橫向的長廊，貼兩次就是長廊接上第二段：

```
 上層（主圖）：
   ┌──────── 第一遍 P1（藍）────────┐ ┃ ┌──────── 第二遍 P2（青綠）───────┐
   The   bark   was   rough   .     ┃  The   bark   was   rough   .
   👁←   👁←    👁←   👁←     👁←    ┃  👁←────────────────────────────── 光照回整個 P1
   泡泡：狗+樹（糊）               ┃       泡泡：樹皮（金）
                                 金色接縫

 下層左：工作站「Prefill」——一排同時亮的機器（長度隨輸入變）
 下層右：工作站「Decode」——一台一個字一個字敲的打字機（長度隨輸出變）
 右上角：準確率儀表（開場 21% → 97%，sc08 回到同一個）
```

- **機制角色**：每個 token 是一個戴半邊眼罩的小讀者，只有朝左的眼睛張開，往左打一束紫色的光（注意力）。光只能往左，碰到自己就停。
- **主角**：bark 這個字。第一遍的 bark 頭上的想法泡泡是狗和樹疊在一起、模糊發抖；第二遍的 bark 泡泡變成清楚的金色「樹皮」。金色只給這個清楚的理解（sc08 的 NameIndex 找到的第 25 個名字也用金色，同一個意思：讀第二遍時才抓到）。
- **開頭和結尾**：開場的準確率儀表 21% → 97% 先閃過、不解釋；sc08 回到同一個儀表，說清楚是哪一題、哪個模型。結尾全景時，第一遍的 bark 還是糊的、第二遍的是金的，兩個泡泡並排。

## 會變的量（都由 tracker 驅動）

- 光的長度：每個讀者的光從自己的位置往左延伸到 P 的起點（第一遍）或整條長廊的起點（第二遍）。同一個函式，只改「能看到的最左邊」。
- 泡泡的清晰度：0（狗和樹疊在一起、模糊發抖）到 1（清楚的金色樹皮）。
- 儀表：一個百分比 tracker。
- 工作站：Prefill 的機器數＝輸入長度、全部同時亮；Decode 的紙帶長度＝輸出長度、一格一格吐出；計時器由兩段時間加總。

## 誇張的地方（每一個都對應一個技術細節）

- bark 的泡泡在兩種意思之間來回閃、讀者冒汗 → 早期 token 的表徵是模糊的混合體（cb#c5）。
- rough 一臉恍然大悟，但回頭伸手拿到的泡泡還是糊的，表情垮掉 → 後面的 token 抓的是早期的、品質低落的 Value（cb#c5）。
- 最後一個字把四個泡泡倒進碗裡猛攪，攪完還是混濁 → 原料不好，Attention Weight 再好也救不回（cb#c6）。
- 問題在前、中間塞長文時，問題讀者被一路擠到畫面外 → 太長會遺忘前面的問題（cb#c7）。
- CoT 的打字機吐出的紙帶長到拖出畫面 → 增加生成 token、延遲與成本上升（cb#c8）。
- Prefill 從 500 台機器變 1000 台，還是「啪」一聲同時亮完 → 平行化，時間差極小（fl#c3）。
