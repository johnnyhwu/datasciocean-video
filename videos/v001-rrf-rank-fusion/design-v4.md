# v001 第四版設計：一張大圖，一路畫下去

**背景：** 使用者看完 v3 後說「還是有粗糙感，離 3Blue1Brown 的精緻順暢差一大截」，並要求「仔細研究那三個 skill，做一支全新的，不要基於原本的修改」。

這次把三個 repo 完整 clone 下來重讀（cth9191 的 SKILL、FORMATS、STORY、FRAME、craft、math STYLE、kit.js、demo；charlie947 的 16 種效果配方、vox、animated-chart、polish；artemnovitckii 的 graph、breakdown、minimal 範本）。v3 只用到表層規則，這次採用的是結構層的做法。

## v3 粗糙的真正原因（對照研究結果）

| v3 的做法 | 研究裡的規則 | v4 改成 |
|---|---|---|
| 8 場各自獨立：淡出 → 章名卡 → 標籤 | FORMATS：「空間型的情節用跟拍鏡頭，一張大圖，不切換」；craft：「一支片最多一個硬切」 | **整支片是同一張大圖**：混合搜尋的管線。鏡頭沿著管線移動，場景邊界看不出來（前一場最後一格＝下一場第一格，用程式比對） |
| 畫面底部「結論列」放整句話 | FRAME 6：「文字活在世界裡，或像這個風格的排版」；math：一個畫面只放一個想法 | **畫面不放句子**。句子交給字幕，畫面只放公式、數字，以及貼在物件上的短標籤（6 字以內） |
| 大量 FadeIn | craft：「banned defaults：所有東西都淡入」；math：「公式要寫出來，不要彈出」 | 公式與數字用 Write；線用 Create；框用 DrawBorderThenFill；由別的東西變來的用 TransformFromCopy／TransformMatchingTex |
| 漸層背景、角落章節標籤、頂端進度條、示意標籤 | craft：「banned：角落的標籤或框」；math：「背景不要漸層」 | 平面深海底色，沒有進度條、章節卡、角落標籤 |
| 數字是寫死的圖 | math：「Trackers：讀數每格都從同一個 tracker 算出來」 | **k 旋鈕、橡皮尺、合併分數都是活的**：ValueTracker 驅動，畫面上的長條與讀數每一格都依卡上公式重算 |
| 靜止 47% | craft：「每 2～4 秒有新東西」「hold 也要有小生命」 | 鏡頭緩推；錘錘眨眼、看向重點；脈衝沿著管線流動 |
| 開頭結尾無關 | FORMATS 不變式 4：「結尾是開頭，被故事改變過」；裝置：flash-forward 開場 | 開場那張文件卡帶兩個不能加的分數；結尾同一張卡被 reranker 排到第 1。開場也先快轉一眼「正確答案被擠下去」 |

## 一句話裝置

**一張金邊的「正確答案」文件，從查詢出發，穿過兩條搜尋、被打分、被排名、被合併，差點被共識擠下去，最後被 reranker 撈回第一名。** 金色全片只給它。

## 大圖的版面（世界座標，由左到右就是資料流）

```
  查詢 ●──► 向量搜尋（藍）──► 向量榜 ┐
       └──► 全文搜尋（橘）──► 全文榜 ┴──► Σ 融合 ──► 總榜 ──►（最後才長出）reranker ──► 第 1 名
```

- 上下兩條通道，藍＝向量，橘＝全文，全片固定。
- 名次＝綠；分數＝紫；k＝淡藍；金＝正確答案。
- 錘錘固定在畫面右下，像 3b1b 的 π 生物，只在講到重點時看向它、反應。

## 鏡頭與段落（對應旁白）

| 段 | 鏡頭 | 發生的事（每一步都是同一個物件變形） |
|---|---|---|
| sc01 鉤子 | 近拍一張文件卡 | 兩條細線從左邊接進來，各寫出一個分數 0.83／12.4 → 寫出「0.83 + 12.4 = ?」→ 單位變形成「公尺＋公斤」→ 分數淡成灰，「RRF」從卡上長出 |
| sc02 為什麼兩個分數 | 拉遠，露出整條管線左半 | 快轉：總榜上金卡往下滑（伏筆）→ 回到現在：查詢點、兩條通道畫出來；脈衝從查詢流進兩條通道（15,000+ 計數器跟著跳）→ 兩份榜單接到中間的空總榜 |
| sc03 分數不能加 | 推到兩份榜單 | 每份榜單下長出它的數線：cosine −1～1、BM25 開口 → 兩條數線並排，刻度對不上 → 正規化：兩條數線縮成 0～1 → **橡皮尺**：最高值從 12.4 拉到 30，B 的讀數每一格重算，1.00 → 0.35 |
| sc04 只看名次 | 停在兩份榜單 | 卡上的分數**變形**成名次 1、2、3（同一個物件）→ 兩個第 1 名滑到一起，等號 → 公式在融合站寫出，名次是綠色、k 是淡藍 → 分母越小，長條越長（1/(60+r) 真的算出來） |
| sc05 算給你看 | 推到融合站 | A、B 兩張卡的名次徽章**從榜單上複製飛進**公式 → 代入、寫出 ≈ 0.0317、0.0311 → 兩條長條比長短，A 稍長 → A 卡在總榜上排到 B 前面 |
| sc06 k 旋鈕 | 融合站右側 | 一個真的旋鈕；轉 k 時，1/(k+r) 的五根長條與 A、B 的合併長條每一格重算：k 小時 B 領先，k 大時 A 領先 → 停在 60 |
| sc07 共識的盲點 | 拉回兩條通道 | 金卡在全文榜「消失」（留下虛線殘影）→ 只剩一路撐著，雜訊卡（4、4）超車，金卡在總榜往下滑（呼應開場快轉）→ 鏡頭往左到源頭：投影片 → VLM 摘要，兩條通道都從**同一份摘要**出發（兩條線收成一點）→ revenue growth ↔ sales increase，全文命中 0 → 權宜：兩路第 1 名釘住 |
| sc08 由淺到深 | 沿管線往右，最後全景 | ① 全文榜往下延伸，截斷線下移，金卡在第 50 名附近被撈回 → ② 全文通道改接 OCR 原文（源頭分開，兩條線重新張開）→ ③ 總榜右邊長出 reranker 站：查詢與每張卡一對一重讀，金卡升到第 1 → **拉到全景**：整條管線＝完整的混合檢索 → 回到開場那張卡，它現在是第 1 名 |

## 規則與檢查（新增到 kit）

- **場景接縫**：`lib/checks/seams.py` 比對每一場最後一格和下一場第一格，差異超過門檻就報錯。
- **相機感知的字級**：鏡頭拉遠時，字的實際大小要乘上縮放比例，仍然不能低於 0.038。
- 沿用 v3 的版面檢查：線穿字、字壓字、停留、平衡。
