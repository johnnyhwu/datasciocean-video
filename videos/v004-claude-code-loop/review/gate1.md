## 候選 A（選定）：Claude Code 的核心只有一個迴圈

- 來源卡：`claude-code-agentic-loop-and-tools`、`claude-code-extension-and-context`、`claude-code-permission-blast-radius`（系列卡，合成一支）
- 類型：機制型
- 預估長度：7～9 分鐘（約 50 條可用主張，5 條 pending 不用）
- 一句話重點：Claude Code 沒有規劃模組，只有一個「做、看、再做」的迴圈
- 暖身例子：我們自己舉例：叫它修一個沒過的測試。讀檔 → 改檔 → 跑測試 → 失敗訊息直接變成下一輪的輸入 → 再改 → 通過 → 回報
- 前置知識：LLM 只會吐字（教科書等級）；context window 的大小有限
- 一張大圖：一個**環形跑道**：中間是凍結的模型，跑道上一圈一圈地跑「想 → 呼叫工具 → 看結果」；每一圈都要經過 harness 的**收費站**（權限檢查、log、Hooks）；跑道外圍是工具箱與 MCP 插座；旁邊一個會漲會縮的 context 水箱（CLAUDE.md、摘要、Subagent 讓它呈鋸齒狀）
- 機制角色：一張**工具呼叫單**（模型每次要動手都得寫一張單子，交給收費站），和前三支的文件、票、讀者不同
- 包裝潛力：搜尋詞「Claude Code」；反差「沒有規劃模組，只有一個迴圈」
- 要講到的限定：這是我們對它的設計解讀；權限是漸進式，不是二元；目標是讓犯錯便宜且可逆，不是完全不犯錯
