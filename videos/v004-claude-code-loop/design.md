# v004 設計紀錄：一圈跑道

## 一張大圖

機制的形狀就是一個圈：模型想 → 開單動手 → 結果寫回紙卷 → 模型再讀。所以大圖是一條**環形跑道**，所有配件都長在跑道周圍。

```
              Skills 書架           Subagent 小跑道
                   ╲                    ╱
   ┌──────┐      ╭──── 想 ────╮
   │ 紙卷  │  ←─ 看          做 ─→ [收費站：權限／log／Hook] ─→ MCP 插座
   │（context）│   │   🔮 凍結的模型   │
   │ CLAUDE.md│   ╰──── 工具箱 ────╯
   └──────┘     放大鏡 鉛筆 逃生門 分身 地球
   ────────────── 沙盒圍籬（sc07 才立起來）──────────────
```

- **跑道**：一個圓（半徑約 2.3），順時針跑。上方「想」、右方「做」（收費站在這段）、下方工具箱、左方「看」（結果回到紙卷）。
- **模型**：圓心一顆結霜的玻璃球，只會「吃字、吐字」，沒有手。
- **紙卷（transcript／context）**：跑道左邊一條直立的長紙卷，每一圈在尾巴接一段（任務、檔案內容、錯誤訊息……）；每一圈開始時，一道光從紙卷流進玻璃球（模型每次都讀整份）。上限是一個虛線框。
- **機制角色「小單」**：一張會跑的工具呼叫單，有眼睛。模型每次要動手就吐出一張，寫著工具名（Read、Edit、Bash…）。它沿跑道跑過收費站（被蓋章）、到工具箱、帶著結果回到紙卷。結果是紅色錯誤時它滿頭汗，但直接再跑一圈。**金色只給小單**（它就是「明確的工具呼叫」這個關鍵設計）。
- **開頭和結尾**：開場畫出一張觀眾想像中的複雜流程圖（規劃器、執行器、檢查器、除錯器），塌掉只剩一個圈；sc06 這張流程圖回來演「脆弱的多階段管線」；結尾全景時流程圖的殘影疊在跑道上，再散掉，剩下的仍然只是一個圈加上配件。

## 三點回顧

- ① 一個迴圈：框住跑道（「做、看、再做」）
- ② 動手先過站：框住收費站（「開單才能動手」）
- ③ 紙卷會整理：框住紙卷（「摘要、分身」）

## 會變的量（tracker）

- 紙卷長度：每接一段就變長；sc08 碰到上限框時前段捲起來，長度掉下去 → 旁邊的曲線畫出鋸齒。同一個 tracker 驅動紙卷與曲線。
- 圈數計數：sc03 每跑一圈跑道上的光跑一次。

## 誇張的地方（每一個都對應一個技術細節）

- 流程圖越畫越亂、塌掉 → 沒有另外掛規劃模組或執行模組（L#c5）。
- 玻璃球伸手碰不到檔案 → 模型本身是凍結的、只產生文字；動手要靠 harness（L#c3）。
- 小單帶回紅色錯誤、滿頭汗，卻聳聳肩再跑一圈 → 失敗只是另一種觀察，迴圈不中止（L#c9）。
- 用嘴說「我要去改檔案了」的泡泡從收費站旁飄過、什麼都沒發生 → 必須明確發出工具呼叫，harness 才有攔截點（L#c8）。
- 流水線遇到沒預期的錯誤卡死冒煙 → 我們認為能從錯誤恢復的單體迴圈比脆弱的多階段管線穩健（L#c10）。
- 爆炸被圍籬擋住 → 沙盒限制錯誤指令觸及的範圍（P#c14）。
- 程式碼山留在外面，只有放大鏡撈到的幾行進紙卷 → 不必把整個專案塞進 context（L#c13）。
