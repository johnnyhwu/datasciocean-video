# v004 規劃：Claude Code 的核心只有一個迴圈

來源：`claude-code-agentic-loop-and-tools`（簡稱 L）、`claude-code-extension-and-context`（E）、`claude-code-permission-blast-radius`（P），concept-wiki `a5ad44f`。pending 主張（L#c12、c15、c16，P#c9、c13）一律不用。

主張類型提醒：L#c1、c10、c18，E#c1、c8、c10、c14、c19，P#c1、c15 是「部落格判斷」→ 用我們的口吻（「我們認為」「在我們看來」），語氣不比卡強。設計參數（L#c5、c6、c8、c9，E#c6、c7、c9、c13、c16～c18，P#c8、c10～c12、c14）主詞是 Claude Code。

## 1. 承諾句

> **Claude Code 沒有規劃模組，只有一個「做、看、再做」的迴圈。**

- L#c1（一個能呼叫工具、觀察結果、決定下一步的 LLM，反覆直到它自己判斷完成）、L#c5（沒有另外掛規劃模組或執行模組）。
- 必須完整說一次的限定：
  - L#c1、E#c1 是我們的設計解讀（「在我們看來」）；
  - P#c1：目標不是讓它完全不可能犯錯，而是讓犯錯便宜且可逆；
  - P#c8：權限是漸進式，不是二元；P#c10：模式由使用者選，不是模型自己決定；
  - E#c17：摘要是把較早的對話摘要成精簡版本，不是盲目截斷。

## 3. 暖身例子與對照表

例子是**我們自己舉的**（旁白說「我們來舉個例子」），檔名、錯誤訊息都是虛構的通用寫法，不放任何看起來像實測的數字。

| 例子的步驟 | 卡上的機制 | 主張 |
|---|---|---|
| 交代任務「修好這個沒過的測試」，寫進紙卷 | transcript 是每一輪的輸入 | L#c11 |
| 模型開一張單：Read 測試檔 → 內容接到紙卷尾巴 | 工具呼叫 → 觀察結果附進 transcript | L#c11、c13 |
| 開單：Edit → 改好 | Edit 是精確字串替換 | L#c13 |
| 開單：Bash 跑測試 → 紅色錯誤訊息接到紙卷 | 失敗測試的 stderr 直接成為下一輪 prompt 的輸入，不需要人類轉達 | L#c6 |
| 模型讀到錯誤，再改一次 | 失敗只是另一種觀察，模型據此重新規劃 | L#c9 |
| 測試通過，模型直接回答、不再開單 → 迴圈結束 | 回應若是最終答案就結束 | L#c11 |
