# 做影片：總流程

九個步驟、四個人審關卡。每一步達到完成條件才能往下走。狀態記在 `videos/<id>/state.json`，用 `lib/state.py` 前進，它會擋住沒有核准紀錄就越過關卡。

## 1. 先看現在在哪

```bash
uv run python lib/state.py list
```

- 有影片停在某個狀態：照下表載入那一步的 skill，從那裡接續。已完成的產物（音檔、場景）有快取，不要重做。
- 沒有進行中的影片：從第 1 步「選題」開始。

## 2. 步驟對照

| # | 狀態 | 載入的 skill | 完成條件 | 之後 |
|---|---|---|---|---|
| 1 | 選題 | `select-topic` | 候選都通過選題標準 | **關卡 1** |
| 2 | 規劃 | `plan-video` | 包裝通過自我檢查；有視覺構想與草圖 | **關卡 2** |
| 3 | 腳本 | `write-script` | 字數落在 3～15 分鐘的範圍 | — |
| 4 | 查核 | `write-script`（後半：派 `fact-checker`） | 每句都有標記，事實句都回得到卡上；`lib/checks/claims.py` 通過 | 不通過就退回第 3 步，最多 3 輪 |
| 5 | 旁白 | `narrate` | 每句都有音檔；總長在範圍內；回聽沒有問題 | — |
| 6 | 動畫 | `animate` | 版面檢查 OK；`visual-checker` 通過；接縫、逐格檢查通過；整片逐秒回看過兩輪 | — |
| 7 | 合成 | `assemble` | 品牌音樂與音效已混入；響度、長度、字幕、格數檢查都通過 | — |
| 8 | 成片 | `assemble`（後半：自檢與審查包） | 所有程式檢查通過；結構指紋已比對 | **關卡 3** |
| 9 | 發布準備 | `publish-prep` | 標題、縮圖、多語說明、章節、上傳清單都備齊 | **關卡 4** → 使用者自己發布 |

發布後使用者會請你回顧，那時載入 `retrospective`。

**順序不能跳**：動畫一定在旁白合成之後做，用實測的時間軸。v001 先用估算的時間軸做動畫，旁白合成後整批對不上。

## 2.1 每支影片固定的部分，和要換的部分

| 固定（頻道識別，照做不用重新設計） | 每支都要不同 |
|---|---|
| 一張大圖加鏡頭跟拍、接縫看不出來 | 大圖本身（機制的形狀）、主角 |
| 開場先丟問題，頻道介紹句放在鉤子之後 | 開場模式、鉤子的內容 |
| 收尾：全景 → 三點回顧 → 錘錘指說明欄 → 頻道片尾動畫 | 骨架、視覺手法、機制角色 |
| 品牌音樂只當標點（片頭、轉場、片尾），不鋪底 | 標題寫法、用哪幾句固定句 |
| 錘錘、配色、字型、字幕樣式 | |

## 2.2 和使用者合作的方式（v001 的經驗）

- **使用者說「還可以」「沒問題」之後，自己再回看一輪。** v001 每次回看都還抓得到東西。
- **回饋是感受時（「粗糙」「吵」「沒活力」），先找出具體原因再改**：對照範例、量測、逐格看。只調一個參數就重交，通常會再被退一次。
- **每次交東西都說清楚**：改了什麼、和上一版差在哪、哪些沒有經過人眼或人耳確認、要他特別看哪個時間點。
- **缺東西要早說**：曲庫、字型、聲音這類要使用者提供或決定的，在用到之前的步驟就問，不要到合成才發現。
- 使用者請你代為決定時（「你來找」「照你的建議做」），就做完整，並把授權、來源、取捨記下來。

## 3. 關卡怎麼交

每個關卡交一份**審查包**（`videos/<id>/review/gate<N>.md`），只放需要使用者判斷的東西；程式通過的檢查只用一行帶過。

| 關卡 | 審查包內容 | 使用者決定 |
|---|---|---|
| 1 選題 | 候選清單（來源卡、類型、預估長度、一句話重點、暖身例子的初步想法），以及 `waiting`／`unsuitable` 的原因 | 選題、合併或拆集 |
| 2 規劃 | 承諾句、段落與時長、暖身例子對照表、每場 2～3 個視覺構想（推薦的附草圖）、2～3 組包裝 | 挑包裝，確認例子與構想 |
| 3 成片 | 成片、被程式標記的項目、和規劃不同之處、結構相似度、這次新增或修改的規則 | 用手機看完並回饋 |
| 4 發布 | 標題加縮圖（A/B 用）、三語說明、章節、字幕、上傳清單（AI use 建議與理由、C2PA 結果、音樂標示） | 定稿並自己發布 |

使用者核准後：

```bash
uv run python lib/state.py approve <id> <N> --note "使用者回饋摘要"
uv run python lib/state.py set <id> <下一個狀態>
```

使用者的回饋直接拿來修改這支影片，只重做受影響的步驟與場景。

## 4. 失敗與中斷

- 查核改寫 3 輪、同一場渲染 3 次、同一句 TTS 3 次仍失敗：**停下來回報**。不換成投影片式的備援畫面，也不放寬規則。
- TTS 碰到每日上限不算失敗：程式會存檔，重置後跑同一個指令就從同一句接續。
- 卡在製作中途被修改了：不自動跟進。維持 `state.json` 記錄的 commit，並通知使用者。
- 對話太長：狀態都在檔案裡，可以開新對話，從 `state.py list` 接續。

## 5. 量測

每支影片在 `videos/<id>/costs.md` 記下：

- 每一步的重試次數、送檢圖片張數；
- 渲染時間、TTS 句數與估計金額；
- 使用者在每個關卡花的時間（問他）。

第一批 2～3 支做完後，整理出最貴的步驟，提出優化方案。
