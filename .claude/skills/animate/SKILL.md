# 第 6 步：動畫

**品質基準是 v001 的成片**（使用者 2026-11-08「相當滿意」，2026-11-16 定版）。開始前先讀這三個檔，新影片照同樣的結構做，換的是內容：

- `videos/v001-rrf-rank-fusion/design.md`：設計怎麼來的，以及每一輪改了什麼；
- `videos/v001-rrf-rank-fusion/scenes.py`：完整範例；
- `lib/kit.py` 的 `Timed` 類別：`at()`、`cam()`、`finish()`、版面檢查。

v001 重做了四版才到這個水準。前三版被退的原因（「像小學生做的動畫」「像投影片」「粗糙」）都寫成下面的規則，照做就不必再走一次。

## 先確認三件事

1. **旁白已經合成，時間軸是實測的**（`timeline.json` 來自真正的音檔）。碰到每日上限時可以先用 `--estimate` 寫，但合成後一定要重渲、清掉 `starts late`（v001：6 個動作晚起步，一路留到成片）。
2. **規劃裡已經定好「一張大圖」是什麼**（見下一節）。沒有就回 `plan-video` 補，不要邊寫邊想。
3. **分鏡審做過了**（`write-script` 的「分鏡審」）：`world.py` 已經有了，`layout-board.txt` 是 OK，審查員沒有 `must`。動畫是把分鏡的每一格接成動作，不是重新設計版面。這一步才發現版面不夠，就回 `world.py` 整張重排，再重出分鏡。

## 工具

- **ManimCE 0.22.1**（Cairo），透過 `lib/kit.py`。環境見 `docs/setup.md`（從零建立用 `scripts/setup.sh`）。
- 畫靜態圖（草圖、縮圖）不設 `YTV_VIDEO`：`PYTHONPATH=lib uv run python -m manim -qh -s <檔案> <場景>`。
- 不混用 ManimGL 的 API。不複製或改作 3b1b/videos 的程式碼。
- 工具已經定案。想換工具先問使用者。

## 結構：一張大圖，鏡頭跟著走

- **整支片是同一張大圖。** 機制本身就是一張圖（管線、流程、座標系）。鏡頭沿著它一站一站走，每一站把那一段畫出來，最後拉到全景。
  - 沒有章節卡、角落標籤、進度條、置中標題卡。章節只寫進 YouTube 說明欄（`chapters.txt`）。
  - 背景一律 `bg: "flat"`（平面深海色）。鏡頭移動時漸層背景會露邊。
- **一個眼睛抓得住的主角。** 全片有一個不變的東西讓觀眾跟著（v001：金邊的「正確答案」文件）。金色只給它。
- **結尾是被故事改變過的開頭。** 開場丟出的問題或快轉的畫面，在結尾兌現（v001：開場被擠下去的正確答案，結尾回到第 1 名）。
- **開場前 5 秒就丟出問題**，不是定義、不是頻道介紹。
- **畫面不放句子。** 句子交給字幕。畫面只放公式、數字，以及貼在物件上的短標籤（6 字以內）。
- **尺度有變化**：至少一個極近的特寫、一個全景。

### 場景之間看不出接縫

每場是一個類別，但觀眾不該看得出換場：

```python
from kit import *

class Sc03(Sheet):                      # Sheet＝這支影片自己的基底類別（v001 scenes.py），放共用的鏡頭與角色方法
    SID = "sc03"
    def construct(self):
        A = self.A
        self.cam_set(STAGE, STAGE_W)                    # 鏡頭接在上一場結束的位置
        W = pipe_base(); self.add(*W.values())          # builder 函式：直接擺出上一場的最後一格
        self.at(A("r1", 0), self.cam(BENCH, 14), run_time=1.3)   # 第一句一開始鏡頭就動
        self.at(A("r1", .5), LaggedStart(*[Write(x) for x in scores], lag_ratio=.12), run_time=1.6)
        ...
        self.finish()                                   # 不淡出；下一場的 builder 要擺出一模一樣的畫面
```

- 每場的「最後一格」寫成 builder 函式，這一場收尾和下一場開頭都呼叫它。顏色、透明度、z 順序都要一致。
- `lib/checks/seams.py` 檢查兩件事：
  - 前一場最後一格和下一場第一格一格不差；
  - **接縫不停格**：前一場最後一個動作結束到下一場第一個動作開始，畫面完全不動的時間要在 **0.8～1.6 秒**。太長像當機（使用者：「轉場的時候會卡住定格幾秒」），太短上一段來不及看。
- 做法：`script.json` 每場 `pad` 用 `[0.15, 0.4]`、最後一句 `hold` ≤ 0.4；每場最後一句的後段（約 0.8）留一個小動作（強調剛講到的東西）；下一場的鏡頭移動從第一句的 0 開始。

## 動作

### 紀律

- **每一個移動、變色、出現，都錨在某一句旁白上**：`self.at(A("句id", 比例), ...)`。標不出對應哪一句，就刪掉。不寫絕對秒數。
- **旁白分開唸的，畫面就分開錨。** 旁白逐一唸出兩三個東西時，每一項一個 `A(句, 比例)`，比例對到那個詞出現的位置。不要一整組放在同一個 `at()`（v001：兩個單位一起寫出來，晚了半句）。
- 同一時間畫面只有一個焦點。動畫不演和旁白不同的事。公式和文字不要無意義地移來移去。
- 每 2～4 秒有新東西；停住的畫面也要有小動作，而且小動作要對應那一句正在講的東西。
- **每一句都要有自己的畫面**，不是只寫出一行字（v003 sc04「順序很敏感」原本 4 秒只有一行字；改成三灰一橘四塊片段，橘色從最前面跳到最後面，才看得出「順序」）。旁白講抽象的話時，找一個會動的東西替它演。
- **操作要演成實體**：講「複製、貼上」就讓鍵帽被按下去（v003 `keycap()`、`press()`），講「讀者回頭看」就讓光往回打。字面上的動作比標籤好懂。
- **真實世界的東西不要粗糙地重畫**：論文、產品介面、網頁，能用真的就用真的（論文首頁截圖，見 `plan-video`），不能用就做到同等精緻。v003 重畫的論文封面被說「非常醜、很不專業」。
- 一次只修一件事，已經滿意的動作不動。

### 語彙

| 要表達 | 用 |
|---|---|
| 公式、數字出現 | `Write` |
| 線、框出現 | `Create`、`DrawBorderThenFill` |
| 由別的東西變來的 | `TransformFromCopy`、`ReplacementTransform`（例：名次從卡片上掉進分母） |
| 同一組依序出現 | `LaggedStart` |
| 強調文字、數字 | `Indicate`（結束會回到原色；要改色另開 `x.animate.set_color()`） |
| 強調卡片、方框、不透明節點 | `kit.Highlight`（只換外框色、放大再回來；`Indicate` 會把整張變成實心色塊）。裡面的圖示要保留原色時加 `inner=False` |
| 一道光沿著線走 | `ShowPassingFlash` |
| 點沿路徑走 | v001 的 `travel()`（最後 20% 淡掉；走完直接 `remove` 會跳一下） |
| 殘影、小配角 | `FadeIn`。**不要所有東西都淡入**，這是前幾版被說粗糙的原因之一 |

不用：粗體大字、膠囊框、徽章、印章、每個動作都彈一下、表格和方框排行榜。一般文字用 `T`（Regular），公式與數字用 `M()`（襯線，變數加 `italic=True`），分數用 `fraction()`。

### 會變的量

- 用 `ValueTracker` 驅動，讀數、長條、指針每一格都依公式重算（v001 的 `Live` 類別、`always_redraw`）。不要寫死前後兩張圖。
- **同一個量的所有表現都接同一個 tracker**：尺、端點、標籤、讀數。v001 尺縮短了，「最高」標籤還留在原地。
- **兩個量相差不到約 5% 時，長度看不出誰大。** 領先的那個另外用顏色標出來，由同一個 tracker 每格判斷，交叉點平滑換色（v001 的 `lead_color`）。
- 觀眾要跟著讀數看的連續變化（旋鈕、滑桿）用 `rate_functions.ease_in_out_sine`。預設的 `smooth` 中段太快。
- 計數器：數字靠右對齊；後綴（「+」）另外淡入；用尾端仍有速度的曲線，不然最後一位會停好幾格才翻。
- 要讓會變的東西出現或消失，直接寫 `FadeOut(live)`、`GrowFromEdge(bars, DOWN)`：`Timed.at()` 會在動畫期間暫停它的 updater。不要用 `self.add()` 讓它直接出現。
- 對 `Live` 或 `always_redraw` 物件做 `Transform` 會壞（點數不同）。要讓它出現，`Write` 最穩。
- **為了示範加的會變數字也是新數字**：要嘛過查核，要嘛不顯示，只讓位置和標籤動。算出來的數字旁邊放小字「代入公式計算」。

### 鏡頭

- `self.cam(點, 寬度)` 回傳動畫，`self.cam_set()` 直接設定。`Timed.view()` 會把點放在主畫面中心。
- **鏡頭移動中不能出現空畫面**：在鏡頭移動的同一個 `at()` 裡用 `Succession(Wait(0.6), AnimationGroup(...))` 開始畫，鏡頭到的時候東西已經在長出來。
- 鏡頭長距離移動時用 `rate_func=rate_functions.ease_in_out_sine`；預設曲線開頭會有約 2 秒幾乎不動。
- **字級會跟著鏡頭縮放**：檢查會乘上 `FW / 鏡頭寬度`。全景鏡頭最寬約 19，那時標籤要用 0.05～0.06。
- **拉到全景之前，先收掉小標籤**（v004）。不要為了讓全景讀得到，把每個標籤都放大：放大後零件之間更擠。全景只留大的東西和主角，標籤在推近時再出現。
- 只有線的物件延伸到畫面外不算越界。文字和卡片不行：推近時要讓它們整個在畫面外，或先淡出。

## 版面與可讀性

- 畫面分區：主畫面（上方 6～78%）、條件標註（78～82%）、字幕區（82～95%，動畫不能進去）。
- 一個**大的中心視覺**佔滿主畫面，垂直置中。內容擠在上半部、下半部空著是第一版被退的原因。
- 字級用畫面高度比例（手機校準過）：註記與小標籤 0.038（下限，低於會報錯）；一般標籤 0.04～0.045；公式與重點數字 0.055～0.075；超過 0.08 只給畫面上唯一的主角數字。
- 線條 2～3px。次要連線用 `LINE` 色、低不透明度。線只接在點上，不穿過文字或別的點；標籤放在線的另一側。
- **間距（v004）**：
  - 文字離別的物件至少是畫面寬的 1.2%（`layout` 會報「太近」）；
  - 不相干的零件之間至少留一個零件寬（約 1～1.5 單位）。

  v004 的零件只隔 0.3～0.6 單位，每一項檢查都通過，使用者看了說「粗糙、太擠」。改一處就撞到別處的時候，就是整張圖的間距不夠，要回 `world.py` 把整張圖拉開，不要一處一處挪。
- **不相干的兩段字至少隔 0.5 單位**，或換行。靠太近會被讀成同一個式子（v001：「3 = 3」接「0▭1」讀成「3 = 30」；「10」上面的「k」讀成 10 的 k 次方；讀數接在箭頭的「?」後面）。
- **附屬物要對準它的主人**：想法泡泡、標籤、讀數要在主人正上方或緊貼旁邊，尾巴指向它（v003 第 1 輪：rough 的想法雲沒對齊 token，被使用者點出來；改成 `bubble_at` 從讀者正上方冒出）。
- **功成身退的標籤要收掉**，不然會和新標籤連讀（v003 回顧的「① 只能回頭看」和還留著的「Prefill」被讀成同一句；框線穿過「Key／Value」標籤）。新標籤出現前，檢查它周圍 0.5 單位內還有誰。
- **一組小物件看起來太小時，整組放大**，不要只調字級（v003 工作站整組放大 1.3 倍，小圖改放到長廊和工作站之間的空檔）。
- 主角移動時 `set_z_index(3)`，從其他東西前面經過，不要被擋住。
- **兩個會動的東西要排先後**（v004）：主角經過閘門、欄杆、手臂這類會動的零件時，零件不要在主角經過的同一時間動。小單還在經過，欄杆就同時放下來，看起來像小單被刺穿。做法：主角先停在前面等，零件動完再走；或主角走過之後零件才動（`Succession(Wait(…), …)`）。`layout` 會報「動作中碰撞」。
- 要表達「經過某個處理」：節點底色不透明、z 比卡片高，卡片沿「起點 → 節點 → 終點」從節點後面穿過去。直線飛過會壓到標籤。
- 整份清單接到下一站：先用大括號（`Brace`）框住再拉線。線從中間某一項出發，會被讀成「只有這一項」。
- 畫面已經滿了就先讓功成身退的東西淡出，再放新的。
- 只強調很小的字幾乎看不出來。要讓觀眾看到這一拍，強調大一點的東西，或加一道 `ShowPassingFlash`。

### 配色

- 同一概念全片同色（`C["概念"]`，在 `script.json` 的 `concepts` 指定），公式和圖形裡的同一個量也同色。每支 4～5 個概念色，其餘用中性色。
- **金色只給最重要的一個元素。** 橘、粉不要和「錯誤」紅用在同一個畫面。
- 不只靠顏色傳達資訊，同時用形狀、標籤或位置區別。

### 舉例與內部用語

- 自己補的例子不掛「示意」標籤，由旁白說「假設」「我們來舉個例子」。
- 畫面上不能出現「卡上」「觀念卡」。

## 吉祥物錘錘

`Plumb(scale).place(點)`，設計與示範在 `docs/mascot/`。

- **只在開場、想通的那一刻、收尾出現**，以及少數插話。不是每場都在。出場時 scale 0.35 以上。
- 招牌：好奇時 `curl()` 讓繩子捲成「？」；想通時 `straighten()` 拉直成「！」，再 `light_on()`。
- 表情很小，要靠動作：`hop()`、`nod()`、`shake_head()`、`tilt()`、`emote("？")`、`look(方向)`、`blink()`、`point_at(點)`。動作都回傳 list：`self.at(t, *p.curl(), ...)`。
- 有台詞時 script 的 `speaker` 寫 `mascot`，場景裡呼叫 `self.lipsync(plumb)`。
- 繩子從畫面頂端垂下來：擺位置前先找一條從頂端到身體都沒有字的直線。鏡頭會動的場景用 v001 的 `plumb_in()`、`plumb_out()`。
- 每支影片另有自己的機制角色，寫在那支影片的 scenes 檔裡。

## 收尾（每支都一樣的結構）

1. **拉到全景**：全片走過的那張大圖，一道光沿整條路流一次。
2. **三點回顧**，每點一句旁白：在圖上用細線圓角框框住對應的元件 → 一條短線往下 → 框的正下方寫「① 短詞」（6 字以內，或一條公式）。講下一點時前一點變淡，三點講完全部回到同樣亮度。元件函式：v001 的 `recap_frame()`、`recap_item()`、`recap_link()`。
   - 框的邊不能穿過圖上的標籤；最右邊的項目留在主畫面 95% 以內。
3. **錘錘說 blog 固定句**：從上方垂下來，`look(DOWN)`、`hop(-0.22)` 往下點兩下，旁邊寫「完整文章／在說明欄」。錘錘本身就是往下指的箭頭。這行字要比回顧小一級、位置低一點，不然會被讀成第四點。
4. **頻道片尾動畫**（最後 20 秒）：最後一場設 `END_BRAND = True`，`kit.Timed.brand_outro` 會把 logo 演出來（海水漲上來 → 錘錘垂進海裡、在深處亮起來 → 寫出 DataSci Ocean）。場上還有錘錘或提示文字時，覆寫 `end_clear()` 回傳收掉它們的動畫；錘錘要拉到鏡頭上緣之外。**這段是品牌識別，每支都一樣，不要改。** 範例：v001 的 `Sc08`。

## 音效

- `sfx=` 只寫種類。只放在真正的轉折：劃掉或否定某個東西、領先換邊、主角被救回或被擠下去、兩條線分開或合起來、三點回顧的每一點、開始轉旋鈕（`knob`）。一般的出現、寫字、鏡頭移動不配。
- v001 最後 48 個，約每 10 秒 1 個。`bell` 全片只用一次，留給最重要的那一刻。
- 新加的 `gain` 先抓 0.35～0.6。Claude 聽不到，審查包要寫明沒有經過人耳確認。種類與實際的聲音檔見 `assemble`。

## 片頭音樂要留的空間

鉤子的最後一句說完，片頭音樂進來。**下一場的 `pad` 前置要留約 2.4 秒**，而且這段畫面要在動（v001：鏡頭拉遠露出整張大圖，`run_time=4.4`）。設定方式見 `assemble` 的「音樂」。

## 寫 Manim 時的坑

- 曲線不要用 `.set_opacity()` 調淡：會連填色一起打開變成色塊。用 `set_stroke(opacity=…)`。
- 不要 `self.add(子群組)` 把群組的一部分加成頂層，原本的群組會被拆散。也不要對子物件單獨下 `.animate`。要調整一部分，用 `*[m.animate… for m in 部分]`。
- 自訂屬性不要叫 `color`、`width`、`height`，會和 Manim 衝突。
- 傳 list 給 `FadeIn` 要先包成 `VGroup`。移除群組用 `self.remove(*group)`。
- `Text.text` 會去掉空白，不能拿來重建字串。
- 停留檢查只看被 `FadeOut` 這類動畫拿掉的物件；鏡頭移開不算拿掉。
- 改了腳本的句子 ID 後，grep 所有 `A("…")`。
- 物件上的例外標記：刻意重疊 `overlap_ok`、刪除線 `cross_ok`、數線 `dots_ok`、一閃而過 `transient`、不檢查 `nocheck`、刻意從後面穿過去 `pass_ok`（卡片穿過不透明節點）、刻意貼著 `near_ok`（標籤貼在自己的框外）。只在真的刻意時用。

## 迴圈（每 2～3 場一輪）

```bash
uv run python lib/render.py <id> -q l --scenes sc01,sc02   # 480p，同時寫版面檢查
uv run python lib/checks/sheet.py <id> sc01                # 每句結束的畫面拼成一張
```

1. **先看 `out/<id>/layout-<場>.txt`**，不是 OK 就先修。它檢查：越界、壓到字幕區、元素重疊、**太近**、**動作中碰撞**（播放中每 1/3 秒取樣一次）、線穿過文字或圓點、實際字級、版面平衡、元素停留不到 1.5 秒、動作晚起步（`starts late`）。
   - `starts late`：前一個動作的 `run_time` 蓋過下一個錨點。縮短前一個動作或把錨點往後移，不要刪動作。
2. 程式通過後，**派視覺檢查員**（`.claude/agents/visual-checker.md`）。每場只給它：縮圖表，加上這場的規格摘要（旁白句子、這場要讓觀眾懂什麼、概念色對照、哪些是舉例）。
3. 依它的判定修，**每場最多 2 輪**，還不過就列進審查包。它提的建議只要是明顯變好就照改，**改動大也要改**，不要留給使用者判斷（v003 留了四項，使用者第一輪就退回）。
4. 同一場渲染失敗 3 次就停下來回報。不要換成投影片式的畫面。

全部場景通過後：

```bash
uv run python lib/checks/seams.py <id> -q l     # 接縫：一格不差＋空檔 0.8～1.6 秒
uv run python lib/checks/frames.py <id> -q l    # 逐格：跳出、空畫面、靜止
uv run python lib/checks/filmstrip.py <id> -q l # 整片逐秒縮圖，Claude 逐張看
uv run python lib/render.py <id> -q h -j 8      # 1080p30，串接成 out/<id>/video.mp4
uv run python lib/checks/seams.py <id> -q h
uv run python lib/checks/frames.py <id>         # 1080p 再跑一次
```

### 整片回看（交關卡 3 之前一定要做，而且要做兩輪）

縮圖表只看句尾，看不到動畫進行中的樣子。v001 每一輪回看都抓到新的問題，包括使用者說「沒問題」之後。

- `filmstrip.py` 每秒一格、去掉重複，約 200 格 22 張。**逐張看**，對照上面的規則，問題列成清單、一次修完再重跑。`--from/--to` 可以只看改過的段落。**主角穿過其他零件、鏡頭大幅移動的段落，另外用 `--step 0.25 --from --to` 加密看**：每秒一格會漏掉擦身而過的那一瞬間（v004 的欄杆刺穿小單，就是審查員從縮圖上碰巧看到的）。
- `frames.py`：✗（明顯跳出、空畫面）一定要修。△ 落在即時讀數或指針上的，把那一格調出來看，只是數字在動就放行，不要為了消掉標記改動畫。
- 靜止段落（≥ 4 秒完全沒有東西在動）補有目的的小動作。v001 成片是 5.7%。
- `filmstrip.py` 會去掉重複的格，只有小動作的段落在縮圖上看起來像靜止。補動作前先看那段程式有沒有 `Indicate`／`Highlight`，並以 `frames.py` 的統計為準。
- 版面檢查偶爾會出現一次就不再重現的警告（v001 的 sc08 一次）。重跑一次確認，重現才修。

### 時間軸變了就全部重來

改句子、重新合成旁白、改 `pad` 都會改時間軸。順序固定：`timeline.py` → 低畫質重渲 → `layout-*.txt` 清到全部 OK → 1080p → 接縫與逐格檢查。只重渲改過的場景用 `--scenes`，但時間軸變了要全部重渲。
