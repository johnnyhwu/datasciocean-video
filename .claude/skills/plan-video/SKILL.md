# 第 2 步：規劃

**為什麼這一步最重要**：影片失敗多半出在「這段要讓觀眾理解什麼」和「整支片長什麼樣」沒想清楚。v001 在這一步沒有定下整體的視覺結構，成片重做了四版。到成片才發現問題，就得整批重做。

產出寫在 `videos/<id>/plan.md`、`videos/<id>/design.md`（大圖的設計，見第 4 節），加上 `videos/<id>/sketches/`（草圖 PNG）。第一次做規劃時先讀 `rules/research-distilled.md` §1、§2、§4。

## 1. 承諾句（一句話重點）

- ≤30 字：觀眾看完會知道的那**一件事**。它同時是標題、縮圖、開場的共同承諾。
- 字面為真，而且回得到卡上。通常來自 thesis 主張，但要用觀眾的語言講。

## 2. 骨架與時長

**機制型**（百分比是暫定值）：

| 段落 | 佔比 |
|---|---|
| Hook：具體問題，加一個具體數字或畫面 | 5–10% |
| 為什麼值得在乎：接回觀眾熟悉的詞 | 約 5% |
| 暖身例子：小而乾淨的例子承載核心機制 | 25–35% |
| 讓觀眾注意到規律，再命名概念 | 20–25% |
| 接回卡上的真實設定與證據 | 15–20% |
| 限制（可略過） | 10% 以內 |
| 帶走什麼，輕提 blog | — |

**事實型**：Hook → 疑問的背景 → 數據逐項揭露 → 解讀 → 限制 → 帶走什麼。

**規則**

- **具體例子先於定義**，定義是推導的終點。公式不出現在前 40% 的時長。
- **例子出場前先給一個「為什麼要看它」**（v003 第 1 輪）：開場幾秒就跳出「The bark was rough」，使用者說「怪怪的」。先交代我們在研究什麼（論文首頁截圖、問題本身），再讓例子走進來，並讓例子從前一個畫面長出來（v003：一條灰色 prompt 裂成五個讀者），不要憑空出現。
- 前置知識用到時才講，不要集中放在開頭。
- 骨架可以變，但要在審查包說明改了什麼、為什麼。**每支影片的骨架和開場模式要和最近幾支不同**（反模板）。
- 依 `rules/speech-rate.md` 換算每段的字數預算。
- **限制段**只放會改變觀眾對結論信任程度的限制，最多 1～2 個，而且只來自卡。論文作者承認的寫「論文作者提到」，卡上的評價寫「這篇文章指出」。卡上沒有就整段略過。
- **結尾**（每支都一樣的結構）：拉到全景，最後一個畫面是**整個方法的概念圖**；三點回顧各對應圖上的一個元件（框起來、下方寫短詞）→ 錘錘說 blog 固定句、身體往下指說明欄 → 系列指引（只限系列影片）→ 20 秒的頻道片尾動畫（固定，不用設計）。開場的快轉在這裡兌現（例：正確答案回到第 1 名）。不提 podcast，不口頭呼籲訂閱。
- **系列**：每集獨立看得懂，有建議順序。回顧前集最多 1～2 句，只重述卡上的內容並過查核；只預告已完成或已排定的下一集。系列名以觀念命名、不用論文名，提 2～3 個候選給使用者；集數不放在標題開頭。

## 3. 暖身例子與對照表

- 一個**小而乾淨、可以手算**的例子，承載卡上的核心機制。卡上有「部落格舉例」的主張就優先用它，它就是 `card_claim`。
- 寫出對照表：`例子的每一步 → 卡上哪條主張的哪個機制`。例子不能和卡上的機制矛盾。
- 例子裡自己補的數字，旁白要說出是舉例（「假設」「我們來舉個例子」），畫面不放「示意」標籤；也不能做得像真實資料。

## 4. 先定「一張大圖」，再想每一場

**整支影片是同一張大圖，鏡頭沿著它走**（v001 重做四版才得到的結構；前三版每場各自獨立，被說「像投影片」「粗糙」）。規劃時就要定下來，寫進 `plan.md`，並畫一張全景草圖：

- **大圖是什麼**：機制本身的形狀，例如資料流的管線、一條時間軸、一個座標系。每一段旁白對應圖上的一站。
- **主角是什麼**：一個觀眾從頭跟到尾的東西，金色只給它（v001：一份「正確答案」文件，穿過整條管線）。
- **開頭和結尾怎麼呼應**：開場的問題或快轉的畫面，結尾在同一個東西上兌現。
- **鏡頭路線**：每一場停在圖的哪裡、哪一場是特寫、哪裡拉到全景。
- **三點回顧各框住圖上的哪個元件**。

把這五項寫成 `videos/<id>/design.md`；之後每一輪使用者的回饋和修改也記在這個檔的後面（範例：`videos/v001-rrf-rank-fusion/design.md`）。想不出一張圖能裝下整個機制時，停下來和使用者討論，不要退回一場一張投影片。

### 大圖是一張地圖，不是一個擠滿配件的中心（v004）

v004 的大圖是一圈跑道，後面每一章的新東西（收費站、工具箱、權限儀表、工作目錄、Skill、Hook、MCP）都貼在跑道旁邊。結果有三個：
- 零件只隔 0.3～0.6 單位，被說「粗糙、太擠」；
- 2:16 之後每一章都是同一個構圖多幾個小東西，四個審查員都說像在列清單；
- 越後面的章節越沒有空間，鏡頭只能拉到最寬，字也跟著變小。

規劃時照這樣設計：

- **每一章在地圖上有自己的一塊地（一站）。** 鏡頭到那一站時，它要能用寬 12～14 的鏡頭填滿主畫面，而且不切到別站。各站之間用主角走的路接起來（v001 是管線，v004 應該是跑道外面再分出幾條岔路，各通到一站）。
- **全景草圖要畫出「整支片會出現的所有東西」，而且照實際大小畫**，包括最後一章才加的配件，以及會跑的主角走過的路線。後面才加的東西沒在草圖上留位置，到時候一定會擠。
- **間距預算**：不相干的零件之間至少留**一個零件寬**（世界座標約 1～1.5 單位）；文字離別的東西至少是全景畫面寬的 1.2%（程式會檢查「太近」）。全景的字級要用全景的鏡頭寬算：寬 19 時，字的 frac 至少 .052。
- **全景只放大的東西。** 小標籤在推近時出現、拉遠前收掉，不要為了全景把每個標籤都放大。
- **每一章要有一個「新的畫面」**：新的一站、一個特寫、一個尺度變化，或一個新角色進場。只在同一個構圖上加標籤，不算新畫面。
- **主角會動的路線要先想好**：它會經過哪些零件、會不會和會動的零件（閘門、欄杆）同時佔用同一個位置。會撞的地方，規劃時就定好「誰先走、誰等」。

全景草圖用 `world.py` 實際畫出來，`-s` 輸出一格，存成 `sketches/panorama.png`，而且要在關卡 2 交出來。不要手寫座標表。

### 每個場景的視覺構想

最高原則：**誇張是手段，講清楚是目的。每一個有趣的動畫，都要對應一個技術細節。**

每個場景提 **2～3 個不同的構想**（不同的比喻、構圖、動作語彙），各附一句理由，挑一個推薦。設計前先問三個問題：

1. 這句旁白在講哪一步、哪個數字、哪個因果？
2. 有沒有一個具體的東西，它的物理行為剛好就是這個機制？例子：期望值＝蹺蹺板的平衡點；量表的格數＝粗尺和細尺；正規化＝一把會伸縮的橡皮尺（v001）。
3. 觀眾只看畫面、不聽旁白，看得懂這一步嗎？看不懂就把缺的那一步畫出來，例如算式的每一項、被丟掉的東西、前後對照。

**可用手法**：

- 畫出「這個數字從哪來」；
- 前後對照證明東西被丟掉；
- 把機率變成積木；
- 每一項算式飛進總和；
- 把數字變成可數的東西，例如百格圖、出票機；
- 一次只改一個變因；
- 統計性質畫成會變的形狀；
- 限定條件本身也是畫面元素；
- 用事件帶出重點，例如蓋印章、碎裂、倒帶、計數器滾動。

**角色**

- **吉祥物錘錘**（`kit.Plumb`）：開場、收尾、或真的需要「帶觀眾往下挖」的時刻才出場，不是每場都在。
  開場的問題讓繩子捲成「？」，想通的時刻拉直成「！」並發光，收尾時出來指說明欄（錘錘本身就是往下的箭頭）。規劃時寫明「！」的時刻放在哪一句。
- **機制角色**：每支影片可以設計一個專屬角色或主角物件（v001：一份「正確答案」文件），它身上發生的事就是機制本身。要和前幾支不同。

**事實型的手法**：依卡上實際有的數據選擇，並寫下理由。

| 手法 | 卡上要有什麼 | 限制 |
|---|---|---|
| 先預測再揭曉（預設） | 可比較的數字 | 揭曉的數字一定是 `card_claim` |
| 具體案例當錨點（預設） | 具體案例 | 案例來自卡 |
| 逐項揭露的圖表（預設） | 一組比較數據 | 縱軸從 0 起，寫出比較對象與分母 |
| 前後對照（預設） | 方法前後的結果 | 兩側條件完全一致 |
| 拉動旋鈕（選用） | 多個設定下的結果 | 只畫卡上的點，點之間不畫平滑曲線 |
| 拆解（選用） | 總數與各部分 | 加總要等於總數 |
| 熱力圖（選用） | 多條件多指標的結果表 | 附圖例 |
| 條件逐層加上去（選用） | 帶條件的數字 | — |

不用「表格停在畫面上念數字」。

**論文圖**：卡上附的圖只當參考（用 Read 實際看），一律依主張重新設計。只畫主張文字裡有的數字。圖上沒標、只能估讀的，只畫示意並由旁白交代；需要精確數字就停下來問。

**論文首頁截圖**（介紹論文的那一拍）：可以放 PDF 第 1 頁截圖，比重畫的封面專業（v003 重畫版被使用者說「非常醜、很不專業」）。條件照 CLAUDE.md「論文首頁截圖」：授權限 CC BY／CC BY-SA／CC0、不讀內文、整頁清楚不打碼、說明欄註明出處。強調標題字用半透明螢光筆色塊（字的像素位置用程式量，不要目測）。授權不符就重畫，並在關卡 2 先告訴使用者。

**草圖**：推薦的構想做一張低解析度草圖，放進 `sketches/<場景>.png`。用 manim 的 `-ql -s` 輸出單格。

**概念色**：這支影片用 4～5 個概念，在 script.json 的 `concepts` 指定（`config/style.json` 的 `concept_pool`），全片同一概念同一色。金色只給最重要的一個元素，不拿來當概念色。

## 5. 包裝（2～3 組）

每組都講**同一個承諾**，但用不同的開場模式：

- 主力：反直覺問題、成果先展示、明確目標；
- 輪替：想像情境、視覺謎題；
- 不用：互動挑戰、痛點承諾、標題快閃。

每組包含：

- 標題：≤30 字，核心承諾放在前 20 字；前半放搜尋詞；英文術語保留原文；全形標點。使用者要**有趣、有節奏**的標題，說明式的會被退（v001 最後選「RRF 排名融合：一個公式、一個旋鈕、一個盲點」）；趣味靠語氣、節奏、反差，每個字都要是影片裡真的講到的事。
- 縮圖文字：2～6 字，補充標題、不重複。
- 縮圖畫面描述：只用影片中真的會出現的元素，另外構圖（做法見 `publish-prep`）。
- 前 30 秒開場稿：30 秒內一定要出現第一個實質內容（問題的線索、關鍵畫面或數字），不是定義。
- 兌現位置：第幾秒、哪個畫面、對應卡上哪一句。
- 一行理由：觀眾為什麼會點、為什麼會看下去。

可以參考 `rules/from-social-media/hooks.md`。使用者偏好清楚直白、口語、活潑的寫法；疑問式與並列式排在前面，反差式排在後面。

**禁止**：

- 「震驚」「顛覆」「竟然」這類字眼；
- 縮圖放影片裡沒有的畫面；
- 用頻道介紹、贊助、長片頭開場；
- 「記得訂閱」；
- 假設情境裡出現看起來像真實資料的數字。

包裝的事實與數字要回到卡上，其他可以自由創作。

**每組逐項自我檢查**，任何一項答不出來，該組作廢重寫：

1. 字面為真嗎？
2. 承諾在第幾秒兌現？
3. 只看標題和縮圖的人會不會誤會主題？
4. 第一個實質內容在第幾秒？
5. 核心主題在標題的前 20 字內嗎？

## 6. 結構指紋

寫 `videos/<id>/fingerprint.json`，格式見 `lib/checks/fingerprint.py`：開場模式、骨架、視覺手法、標題寫法、機制角色、固定句。全頻道固定的東西（一張大圖跟拍、三點回顧、品牌音樂、片尾動畫）不要列進去，它們是識別，不是要換的部分。然後跑：

```bash
uv run python lib/checks/fingerprint.py <id>
```

相似度太高就換做法，再交關卡 2。

## 7. 關卡 2

審查包寫在 `videos/<id>/review/gate2.md`：承諾句、骨架與時長、暖身例子對照表、**大圖的全景草圖與鏡頭路線**、每場的構想與推薦（附草圖）、包裝 2～3 組與自我檢查結果、結構相似度。

- 使用者如果選了沒附草圖的構想，渲染前要補一張給他確認。
- 核准後執行 `state.py approve <id> 2`，再 `set <id> 腳本`。
