# 第 9 步：發布準備

**使用者自己發布。** 只準備素材，不上傳，也不呼叫任何上傳 API。

## 1. 標題與縮圖（A/B 測試用，每支都做）

依關卡 2 選定的開場與承諾，做 2～3 組「標題＋縮圖」。各組只換說法，不換承諾。

**標題**

- ≤30 個中文字，核心承諾放在前 20 字；
- 使用者要的是**有趣、有節奏**的標題（v001 選了「RRF 排名融合：一個公式、一個旋鈕、一個盲點」），四平八穩的說明式標題會被退。趣味靠語氣、節奏、反差，每個字仍然要是影片裡真的講到的事；
- 前半放觀眾會搜尋的詞，後半放問題或反差；
- 英文術語保留原文，全形標點；
- 少用全大寫與 emoji，不用誇大字眼。

**縮圖**

- **另外做一張專用構圖**，只用影片裡出現的元素：寫一個 `videos/<id>/thumb.py` 的 `Thumb` 場景，用 `manim -qh -s` 輸出單格，再縮成 1280×720（範例：v001）。**不要拿成片截圖加字**：v001 第一版這樣做，元素太小、字壓到內容，使用者說「好醜」。
- 構圖：一行大字（佔畫面高約 20%）、一個放大的主視覺（公式或關鍵圖）、發光的錘錘在一側，底部可以放片尾的海。做完縮到 320×180 看一次，字和主視覺都要看得清楚。
- 文字 2～6 字，補充標題、不重複；構圖簡單、字大；至少 1280×720。
- 不用寫實的 AI 人像、真人照片，也不放影片中沒出現的公司 logo。
- 品牌色、吉祥物可以出現。

在結構指紋裡記下每組的開場模式和標題寫法，供之後分析成效。

## 2. 說明欄（繁中，另附英文與簡體版）

1. 開頭兩三行：用承諾句改寫的摘要。
2. 延伸閱讀：對應的 blog 文章連結（卡的 `sources[].url`）。論文資訊只在卡上或文章裡有時才列。
3. 系列影片：其他集的連結。
4. 章節（`videos/<id>/chapters.txt`，由場景自動算出）。
5. 音樂標示：看 `mix.json` 的 `music_used`。品牌音樂是 Pixabay Content License，不需要標示；用到標 CC 的曲子才要附。
6. 使用備案聲音時，加一行「旁白由 AI 語音合成。」

不放 podcast 連結。英文與簡體版**只翻譯**，不多加說法。

## 3. 章節與片尾畫面

- 章節規則：第一個是 0:00、至少 3 段、每段至少 10 秒。`timeline.py` 已經檢查過。
- 片尾畫面由使用者手動設定：放系列或下一支影片，加上訂閱按鈕。影片最後 20 秒是頻道片尾動畫，錘錘和字標在正中間，**左右兩側是空的**，元件放在那裡；片尾畫面只能放在最後 5～20 秒。

## 4. 多語

- 簡體字幕：`out/<id>/deliver/subs.zh-CN.srt`。由 OpenCC 轉換，再套 `config/zh-cn-terms.yaml` 的用語修正。
- 英文用 YouTube 自動配音（繁中配英文）。還不能用時，改交付英文翻譯字幕（SRT），只翻譯。

## 5. 上傳清單（`videos/<id>/upload.md`）

- [ ] 影片檔：`out/<id>/deliver/<id>.mp4`
- [ ] 字幕：繁中、簡體 SRT（備案時另附英文 SRT）
- [ ] 2～3 組標題加縮圖（A/B 測試）
- [ ] 三語標題與說明欄
- [ ] 章節
- [ ] **AI use 建議答案與理由**：
  - 用使用者的複製聲音 → **No**。YouTube 官方把「複製自己的聲音做旁白」、非寫實動畫、AI 協助腳本與標題縮圖都列為不需揭露。
  - 用 Gemini 預設聲音 → **Yes**。官方沒有明文規定；選 Yes 只會在說明欄展開處顯示標籤，官方說不影響推薦與營利。
- [ ] C2PA 檢查結果（`deliver/checks.json`）。複製聲音的輸出帶有 C2PA，要回報最終檔有沒有殘留。
- [ ] 音樂標示是否已附
- [ ] 提醒：加入系列播放清單、設定片尾畫面

## 關卡 4

把上面全部交給使用者定稿。他發布後，記下影片網址與發布時間，然後執行：

```bash
uv run python lib/state.py approve <id> 4 --note "…"
uv run python lib/state.py set <id> 已發布
```

接著提醒他：可以請你做這支影片的回顧（`retrospective`）。
