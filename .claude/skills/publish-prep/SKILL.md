# 第 9 步：發布準備

**Claude 不直接公開。** Claude 準備素材、過關卡 4、上傳成私人；使用者說定版之後，排程在週六 09:00（台北）自動公開（使用者 2026-11-23）。不得上傳成公開、不得把私人直接改成公開。

範例：`videos/v001-rrf-rank-fusion/` 的 `upload.md`、`upload.json`、`thumb.py`、`review/gate4.md`。

**1、2 節（標題、縮圖）在成片自檢時就先做草案**，因為觀眾體驗自審（`make-video` 第 4 節）要連標題、縮圖一起看；自審的縮圖排名與點擊意見拿來定稿。

## 1. 標題

標題和頻道說明由 Claude 自己寫，不用 Gemini（使用者 2026-11-21 試過 Gemini 3.8 Flash 後決定：「標題和頻道說明都用你的好了，gemini 做 tts 就好」）。

給使用者 **4～5 個候選**，列成表：標題、有趣在哪、要注意的地方，並說出你建議哪一個、為什麼。

- ≤30 個中文字；英文術語保留原文；全形標點。
- **開頭先讓人看懂、想知道答案**：用白話講 AI 在做什麼、哪裡出了怪事（具體數字、矛盾、問句）。手機只顯示前十幾個字，那幾個字一定要有「AI」或觀眾認得的詞。觀眾沒聽過的方法名（CER 這種縮寫）放在「｜」後面給搜尋用；只有大家熟悉的名稱（RAG、ChatGPT）才放前面。使用者 2026-11-21 看到「CER 信心加權投票：讓猶豫的票變輕」：「實在太不吸引人了，你自己想想你在 youtube 看到這個 title 會想點進來嗎」。原因：開頭是沒人懂的縮寫和術語、看不出跟 AI 有關、結論句要看完影片才懂、沒有懸念。
- 交候選前自問：「我在推薦列表滑過去，只看到前 15 個字，會停下來嗎？」
- **使用者要有趣、有節奏的標題。** v001 第一輪給的三個說明式標題被退（「可以再浮誇一點」「再更有趣一點」），最後選的是「RRF 排名融合：一個公式、一個旋鈕、一個盲點」：短、三拍、每個詞都對應影片的一段。
- 趣味靠語氣、節奏、反差、懸念。**每個字都要是影片裡真的講到的事**；卡上沒有的比較（「更準」「最強」）不能用。
- 只在某個條件下成立的說法（v001：「第 3 名贏第 1 名」只在 k = 60 時），要在候選旁邊註明風險。
- 使用者選了方向但還不滿意時，以他選的為底再給 3～4 個變化。

## 2. 縮圖：一個標題、三張縮圖

**觀看數＝觸及 × 點閱率。** 觸及主要看題目有沒有人要；縮圖和標題只能影響點閱率，但這是我們能控制的那一半。使用者對「元素小、暗、像片內截圖」的縮圖不滿意（v001「好醜」、v002「實在不太滿意」）。

**做三張**：`videos/<id>/thumb.py` 寫 `ThumbA`、`ThumbB`、`ThumbC` 三個場景，輸出成 `thumbs/A.png`、`B.png`、`C.png`（1280×720）。三張給 YouTube Studio 的「測試與比較」：標題固定，只換縮圖，由 YouTube 依觀看時間選出贏家。

```bash
YTV_VIDEO=<id> PYTHONPATH=lib:videos/<id> uv run python -m manim -qh -s --media_dir out/<id>/thumb videos/<id>/thumb.py ThumbA ThumbB ThumbC
```

**三張各押一種不同的槓桿**，不要做同一張圖的三種配色：

| 槓桿 | 例子（v002） |
|---|---|
| 對錯：多數／直覺的答案打叉，對的打勾 | 「AI 多數決 選錯了」：三顆冒汗的票 375 ✗、兩顆笑臉 400 ✓ |
| 表情：一個有表情的角色放大到佔半個畫面 | 「AI 很猶豫 也算一票？」：一顆冒汗發抖、拿著 375 的巨大選票 |
| 數字：一個比較當主角 | 「AI 投票 看信心」：天平倒向 400：1.88，375：1.70 被翹起 |

每張都要做到：

- **一眼看懂主題**（最重要）：使用者 2026-11-21：「thumbnail 應該是要讓人一看就知道這個影片在講什麼主題，然後吸引觀眾點擊」。只有角色和天平、沒有主題的縮圖被退。大字一定要有觀眾認得的主題詞（「AI」加情境，例：「AI 多數決 選錯了」「AI 很猶豫 也算一票？」），不要只放方法縮寫或抽象的一句話；畫面放片中具體的東西（真的答案數字、例子），讓人看得出「這是在講 AI 怎麼做某件事」。
- **站在滑手機的人的角度**：使用者 2026-11-21：「站在一個笨笨的人類的角度…人類常常滑過去，除非真的 catch his eyes」。最後定案的 v002 縮圖 `thumbs/D.png` 只放兩個超大數字（375 打紅叉、400 發光打勾）、底下小小的 3 票對 2 票，大字「AI 多數決 竟然錯了」。用人人都懂的符號（✗ ✓、大數字），大字要口語、不用課本詞，畫面上能讀的東西越少越好。
- **一個主角，放大**：佔畫面一半左右。主角最好是**有表情的角色**（機制角色或錘錘），因為我們沒有真人的臉，角色的表情就是那張臉。
- **一句大字**：2～8 字（可分兩行），佔畫面高約 15～20%，亮金色（比片內的金色更亮）加深色描邊和陰影。**不重複標題的字**，要和標題合起來才是完整的一句話。
- **比片內更亮、對比更高**：片內是安靜的深海；縮圖刻意比較吵。底色中間用亮青綠光往外變暗，不要整片暗色。線條加粗到片內的 3～4 倍。
- **畫面乾淨**：除了大字和主角的一兩個數字，不放其他字，不放小讀數。
- 只用影片裡出現的元素；每一張的承諾影片都要講到。字面要寫「這句話在片中哪一句」（例：v7「票比較少的那邊，反而贏了」）。
- **不要拿成片截圖加字**（v001 第一版：元素太小、字壓到內容）。不用寫實的 AI 人像、真人照片、影片中沒出現的 logo。

**自己檢查**：把三張排成一張對照表，同時看原尺寸和 240×135（手機推薦列表的大小）。小圖上要看得出大字、主角的表情；元素互相穿過、字被切到就修。舊版縮圖不要覆蓋，改名成 `thumb-v1.png` 保留。

## 3. 說明欄（繁中，另附英文與簡體）

1. 開頭兩三行：用承諾句改寫的摘要。
2. 延伸閱讀，依序放：
   - 我們的文章：`lib/cards.py` 輸出開頭的 `blog=`。
   - **原始論文**：使用者 2026-11-21：「除了放我的 post link 也可以放原始的 paper 或是 technical blog 的 link」。優先放正式發表版（ACL Anthology、OpenReview、期刊頁），再放 arXiv 摘要頁（`arxiv.org/abs/…`，不放 PDF 直連）。卡上有 arXiv 編號就用它；沒有的話，用卡上的方法全名和發表會議（常在 `sources[].article_title`）上網搜尋。
   - **官方技術部落格**：作者或機構有官方介紹文（例：Google Research、OpenAI 的 blog）才放，沒有就不放。不放第三方的解說文。
   - 只拿網址和標題來確認是同一篇：論文標題、會議要和卡對得上。**不讀它的內容**，影片內容還是只來自觀念卡。關卡 4 的審查包列出這些連結和查證方式，請使用者確認。
   - 英文版寫 Paper／Official blog，簡體版照譯。
3. 系列影片：其他集的連結（有的話）。
4. 章節：`videos/<id>/chapters.txt`（`timeline.py` 產生並檢查過：第一個是 0:00、至少 3 段、每段至少 10 秒）。
5. 音樂標示：看 `out/<id>/mix.json` 的 `music_used`。品牌音樂不需要標示；用到標 CC 的曲子才要附。

不放 podcast 連結。英文與簡體版**只翻譯**，不多加說法。簡體字幕由 `package.py` 產生（OpenCC 加 `config/zh-cn-terms.yaml`）。

## 4. 上傳清單與設定檔

- `videos/<id>/upload.md`：給使用者看的清單。檔案路徑、定案的標題與縮圖、三語說明欄、上傳時的設定、發布後要手動做的事。
- `videos/<id>/upload.json`：給 `lib/upload.py` 讀的設定，格式照 v001。

**AI use 的建議答案**（`upload.json` 的 `contains_synthetic_media`）：

- 旁白是使用者本人的複製聲音、畫面是非寫實動畫 → **No**（false）。YouTube 官方把這兩種列為不需揭露。
- 改用 Gemini 預設聲音 → **Yes**（true），說明欄加一行「旁白由 AI 語音合成。」

其他要寫進清單的：C2PA 檢查結果（`deliver/checks.json`）、分類（預設「科學與科技」）、標籤。

## 5. 關卡 4

審查包 `videos/<id>/review/gate4.md`：標題候選與建議、縮圖、說明欄有沒有要改、上傳設定。使用者定稿後記錄核准：

```bash
uv run python lib/state.py approve <id> 4 --note "定案的標題；使用者的原話"
```

## 6. 上傳成私人

1. 預演，把輸出整理給使用者看：`uv run python lib/upload.py <id>`（不連線）。
2. **問「現在上傳嗎」，得到同意才執行。** 每支都要問，先前的同意不算。
3. 執行 `uv run python lib/upload.py <id> --go`，用背景執行：瀏覽器可能跳出 Google 授權頁，要等使用者操作。先告訴他會看到什麼（選帳號 → 「尚未驗證」按繼續 → 勾權限）。
4. 中途失敗就重跑同一個指令，已完成的步驟會跳過。
5. 完成後把 Studio 連結給使用者，請他做三件事：
   - 檢查標題、說明、縮圖、字幕、「經過變造的內容」那一項；
   - 設定片尾畫面（只能放在最後 5～20 秒；錘錘和字標在正中間，元件放左右兩側）和自動配音；
   - 縮圖 →「測試與比較」，傳入 `thumbs/A.png`、`B.png`、`C.png`（API 只能設一張，就是 `upload.json` 的那張）；
   - 看完說「定版」（或要改什麼）。
6. **使用者說定版之後排程**：`uv run python lib/upload.py <id> --schedule`（預演，印出日期）→ `--schedule --go`。規則：下一個週六 09:00（台北）、至少 24 小時後、不和其他影片撞期；使用者指定別的時間就加 `--at 2026-12-05T09:00`。排完告訴使用者日期，並提醒片尾畫面、縮圖 A/B 測試要在那之前於 Studio 設好。使用者自己在 Studio 排程時，跑 `--status` 把排程時間記下來。

常見狀況：

- **「403 access_denied」「尚未完成 Google 驗證」**：登入的帳號不在 OAuth 同意畫面的測試使用者名單裡。請使用者到 Google Cloud 的「目標對象」把那個 Gmail 加進去。
- **授權過期**：同意畫面在測試狀態時授權只有 7 天，程式會自動重新要求授權。
- **縮圖失敗**：頻道還沒完成電話驗證。請使用者在 Studio 手動傳。
- 第一次設定的步驟在 `docs/youtube-upload.md`。不要讀出或印出 `secrets/` 裡的檔案；要確認時只用程式檢查欄位名稱。

上傳後要改標題、說明欄、標籤、翻譯：改 `upload.json` 後直接跑 `uv run python lib/upload.py <id> --update-meta --go`（不送隱私設定，送完會確認隱私沒變）。要換縮圖：把 `upload-result.json` 的 `thumbnail` 改成 false 再跑 `--go`（影片、字幕已上傳的會跳過）。不要請使用者手動貼（使用者 2026-11-22：「你不能自己 upload 嗎」）。影片還是私人時**不用先問**，改完告訴使用者改了什麼（「以後都可以直接改，反正最後會由我 review 然後才會設定成公開」）；影片已經公開時，改了觀眾馬上看得到，要先問。

**換成新版的成片**（v004：使用者看完私人版後要求改，改完要重新上傳）

已上傳的影片不能換檔案，只能另外上傳一支私人影片。
1. 先問使用者要不要上傳，這算一次新的上傳。
2. 把 `upload-result.json` 改名成 `upload-result-old-<舊影片 ID>.json`。
3. 重跑 `upload_draft.py`：章節時間通常變了。
4. 照上面第 1～3 步上傳。

舊的私人影片要刪掉的話，請使用者在 Studio 刪：`upload.py` 沒有刪除功能，專案也規定不能用別的方式呼叫 API。刪了之後，在舊紀錄檔加一行 `deleted`。

所以**第一次上傳私人前，先讓使用者在本機看過成片**（附開啟指令），這樣使用者第一輪的回饋不用等上傳；除非使用者說想用手機在 YouTube 上看。

API 做不到、要使用者在 Studio 手動做的：片尾畫面、自動配音、標題縮圖的 A/B 測試、刪除影片。

## 7. 公開之後（排程時間到了，或使用者自己按了公開）

`analytics.py --due` 碰到排程時間已過、狀態還沒改的影片會印提醒，照提醒做：

```bash
uv run python lib/state.py set <id> 已發布      # 有排程時，發布時間記成排程時間；成效追蹤靠它算到期日
uv run python lib/analytics.py --due            # 確認 d7、d28 的到期日有列出來
```

告訴使用者 d7、d28 哪一天到期，以及到時候 Claude 會自己抓數據（`retrospective` 的「成效追蹤」）。

報這支影片的 **Gemini 總花費**（目前只有 TTS）：`uv run python lib/gemini.py cost <id>`。使用者 2026-11-21：「每次完整產出一段影片的時候都可以告訴我 gemini 總花費 包含 tts and llm」。

接著跑一次頻道總覽（`retrospective` 第 1 節的「每支影片做完之後」），把結果和下一支打算怎麼改講給使用者聽。然後問他要不要 commit。
