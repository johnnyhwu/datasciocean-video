# 第 3 步：寫腳本　＋　第 4 步：查核

## 寫腳本時只守一條：事實來自卡

其他表達完全自由。標記與查核是寫完之後的事，寫的當下不用想標記，否則腳本會變死板。

### script.json 格式

```jsonc
{
 "title": "影片標題（暫定）",
 "gap": 0.25,                         // 句間固定間隔（秒）
 "scene_pad": [0.15, 0.4],            // 場景前後留白：短，接縫才不會停格
 "end_screen": 20,                    // 最後 20 秒：頻道片尾動畫
 "chapter0": "開場",                  // 0:00 那一章的名稱
 "concepts": {"名次": 0, "分數": 1},  // 概念 → config/style.json 的 concept_pool 索引，全片同色
 "speakers": {"mascot": {"label": "錘錘"}},   // 非旁白說話者的字幕前綴
 "music_punct": {…},                  // 品牌音樂出現的位置，見 assemble
 "scenes": [
  {"id": "sc01", "name": "老是平手", "bg": "flat",
   "chapter": [1, "章名"],             // 只用來產生 YouTube 說明欄的章節；畫面上沒有章節卡
   "sentences": [
     {"id": "a1",
      "display": "叫它給 1 到 5 分。",         // 顯示稿：畫面與字幕用
      "say": "叫它給一到五分。",              // 唸法稿：給 TTS（省略就唸 display）
      "style": "語氣好奇，像在丟一個謎題",     // 可省略；要短
      "speaker": "narrator",                // narrator｜mascot｜…（見 config/voice.json）
      "hold": 0.3,                          // 念完多停幾秒，給動畫時間；每場最後一句 ≤ 0.4
      "screen": ["1～5 分"],                 // 這句時畫面上會出現的文字或數字（也要查核）
      "visual": "量尺從 1 跳到 5，兩個回答都停在 4"}   // 分鏡稿：這句畫面上發生的事件（不上畫面、不查核）
   ]}
 ]
}
```

三個場景的 `pad` 要另外設（其他用預設）：

- 第一場 `[0.3, 0.4]`；
- 鉤子之後那一場（頻道介紹句開頭）`[2.4, 0.4]`：前 2.4 秒給片頭音樂；
- 最後一場 `[0.15, 2.4]`：片尾動畫前停一下。

**畫面上有符號或數字的句子一定要寫 `say`**。v001 有一句漏寫，TTS 把「1 ÷ (k + 名次)」連括號一起念出來。

### 口語稿規則

- 句子短，一句一個重點，用台灣口語的繁體中文。中英之間加半形空格（和 podcast、卡一致）。
- **講到一個零件前，先說它在整個系統的哪裡**（v003 第 1 輪：講 Key／Value 時使用者要「強調這是 attention 層的機制」）。一句太擠就拆兩句：先定位（「這發生在 Attention 層」），再講細節。
- 英文縮寫第一次出現時，附全名和一句話說明。方法本身的全名或譯名如果不在卡上，查核員會標成要使用者決定：寫進去，並在關卡 3 提出來（v001 的 RRF 全名，使用者同意保留）。
- **唸法稿**：數字寫成國字（31% → 百分之三十一）。多音字或英文容易唸錯的，改寫唸法稿繞過，並記進發音對照表 `rules/pronunciation.md`。可參考 `rules/from-podcast/NORMALIZATION.md`、`NARRATION.md`。
- **數字三件事要齊**：量的是什麼、比較對象、限定條件。比例要寫出分母。
  - 取整不能改變意思：31% 可以說「約三成」，不能說「超過三成」。方向詞要一致。
  - 每個關鍵數字的限定條件，**旁白至少完整說一次**，畫面再補細節。
- **寫法依錨點類型**（`rules/from-social-media/anchor-writing-rules.md`）：
  - 設計參數：主詞是方法名。
  - 官方宣稱：主詞是宣稱方。
  - 原作者解讀：寫「論文指出」。
  - 部落格推論、部落格判斷：以作者口吻寫，語氣不能比卡強。
  - 部落格舉例：標明是例子。
- **限定語（「我們認為」「在我們看來」）每段最多說一次**，放在那段第一個判斷句。後面的句子承接這個限定，不用再加；改用不帶立場的句型（「與其說…不如說…」「關鍵在於…」）。
  - 全片的限定語超過 4 次就要重寫。
  - 「語氣不能比卡強」說的是不加強語氣（不寫「一定」「最」「證明」），不是每一句都要加前綴。
  - v004：一開始寫了 12 次，四個審查員都說太多，使用者也說「不用一直強調」，後來在成片階段才改成 3 次，代價是重新合成 11 句、重新查核兩輪。
- **`author_confirmed` 的主張取保守寫法。** `pending` 的一律不用。
- **代入公式計算**（公式與數字都要來自卡上）：可以把卡上的數字代進卡上的公式，把結果算給觀眾看，觀眾比較好懂。
  - 公式與每個代入的數字都要來自卡上的主張。例如 c5 的公式代入 c6 的 k = 60，加上 c9 的名次。
  - 畫面上要有「代入公式計算」小字。
  - 算出來的結果不能拿來推出卡上沒有的結論，例如「所以 k 越大越好」。
  - 例子會隨參數改變結論時，要說清楚是在哪個參數下算的，例如「在 k = 60 時」。
- **觀眾看得到的字不出現內部用語**：觀念卡、卡上、這張卡、「作者說／作者認為」。作者的經驗改成「我們自己做……時」（`claims.py` 會檢查）。
- **收尾**：拉到全景 → 三點回顧，每點一句、各對應全景圖上的一個元件（第一、第二、第三）→ 錘錘說 blog 固定句、往下指說明欄。三點要涵蓋整集的主線（問題、機制、限制或補救），每點都要過查核；一句太長就拆兩句。
- **畫面上的字和旁白用同一個詞。** 旁白說「紙卷」，畫面就寫「紙卷」，不寫 transcript；要放英文原名，第一次出現時寫成「紙卷（transcript）」，而且旁白也要說到。（v004：觀眾要自己把 transcript 對到紙卷。）
- **不寫清單句。** 「它有 A、B、C、D 四種工具」這種句子，畫面只能跟著列清單（v004 的工具段 3:05～3:46，四個審查員都說是最可能滑走的地方）。改成同一個例子裡發生的事件：「要改檔案，它開一張 Edit 單；要跑測試，換一張 Bash 單」，讓每一項都有一個動作可以演。
- 固定句只能照 `rules/fixed-lines.md` 的模板填變數。
- 字幕：每句 `display` 要能放進 2 行、每行約 18 字。太長就拆句。
- 第一稿常常太長。刪的順序是重複的鋪陳 → 合併句子 → 把細節交給畫面。**不要砍使用者重視的細節與限定條件。**

### 寫完先跑

```bash
uv run python lib/timeline.py <id> --estimate      # 估算片長、場景長度、字幕斷行與每秒字數
uv run python lib/checks/fonts.py <id>             # 缺字與簡體字
```

片長要在 3～15 分鐘內（不含片尾 20 秒）。字幕問題在這裡就修掉。

**寫完自己從頭唸一遍，站在聰明外行的位置問**：哪一句會讓人離開？哪個詞第一次出現卻沒解釋？前 30 秒有沒有實質內容？腳本定了之後再改，後面的旁白、時間軸、動畫都要跟著重做，所以在這裡多花時間最划算。

### 分鏡稿：每一句都寫下畫面（和腳本一起寫）

每句加一個 `visual` 欄位，寫**這句時畫面上發生的事件**。要寫成「誰對誰做了什麼」，例如「Bash 單子走進終端機，跑出紅色 FAILED」；不要寫成「顯示工具箱」。這個欄位給自己、分鏡和審查員看，不會出現在畫面上，也不用查核。

寫完逐句看：
- **連續 3 句以上的 `visual` 都是「加一個標籤／亮一下」**：觀眾會在這裡滑走。改寫句子，讓它有東西可以演，或把這幾句合併。
- **一章裡所有的 `visual` 都在同一個鏡頭**：這一章缺一個新畫面（見 `plan-video` 第 4 節）。
- **寫不出 `visual` 的句子**：通常是抽象的總結句。刪掉，或改成一個具體例子。

## 第 4 步：查核

1. 執行 `uv run python lib/state.py set <id> 查核`。
2. **派查核員**（讀 `.agents/agents/fact-checker.md`，用 `define_subagent` ＋ `invoke_subagent` 派任）。只給它：
   - `videos/<id>/script.json`；
   - 來源卡 ID 清單（它自己用 `lib/cards.py` 讀）；
   - `plan.md` 裡的暖身例子對照表；
   - 有重畫論文圖時，列出圖檔路徑和重畫的規格。
   
   第 2 輪以後，**只給改過的句子 ID**。
3. 查核員寫 `videos/<id>/factcheck.json`，再跑：
   ```bash
   uv run python lib/checks/claims.py <id>
   ```
4. **不通過**就回到寫腳本，只改被點名的句子。規則卡住好內容時：
   - 先換一種表達；
   - 還是不行，就列進關卡 3 的審查包，交給使用者決定；
   - 遇到不屬於任何標記的內容，停下來問使用者。

   查核改寫最多 3 輪，還不過就停下來回報。
5. **通過**：`factcheck-program.json` 的 `flagged_for_gate3` 留著放進關卡 3 審查包。接著做分鏡審。

## 分鏡審（查核通過之後、合成旁白之前；v004 之後加）

到這裡句子還能免費改。旁白合成之後，改一句就要重新合成、重新查核、重渲。結構問題在這裡抓。

1. **寫 `videos/<id>/world.py`**：大圖的所有零件，以及每一場最後一格的 builder 函式。動畫也會用同一份，不是丟掉的草稿。
2. **寫 `videos/<id>/board.py`**，繼承 `kit.Board`（用法見 `lib/kit.py` 的 `Board` 說明）。
   - 每句至少一拍，有事件的句子拍事件發生後的樣子；
   - 鏡頭用之後動畫真的會用的位置和寬度；
   - `note` 抄這句的 `visual`。
3. 渲染並拼圖：
   ```bash
   uv run python lib/timeline.py <id> --estimate
   YTV_VIDEO=<id> PYTHONPATH=lib:videos/<id> uv run python -m manim -qm videos/<id>/board.py <類別名>
   uv run python lib/checks/board.py <id>          # → out/<id>/board/sheet-*.png
   ```
4. **先看 `out/<id>/layout-board.txt`**：越界、重疊、太近、字級。全部清掉，紅框的格子也要清掉。然後自己逐張看分鏡：
   - 有沒有構圖一樣的連續好幾格？
   - 全景格子裡的字讀得到嗎？
   - 主角經過的地方空不空？
   - **核心機制的那一次轉換有沒有一格演出來？**（v005：機率長條 → 積木）只有前後兩格、中間靠旁白交代，就是 must。
   - **要比較的兩個數字，在尺上分得開嗎？** 差不到 5% 就加放大框（v005：0～5 的尺看不出 4.16 和 4.3 的差別，改成只看 4.0～4.4 的放大框）。
   - **並列的幾項是不是各有一個道具和事件？** 只在同一塊板上換字，就是清單。
   - **開場的主角，到後面幾站還認得出來嗎？** 認不出來，就把它縮成小卡帶著走。
5. **派審查員**：照 `make-video` 第 4a 節，`uxpack.py <id> --board`，派 2 個新的 `ux-reviewer`，結果寫進 `review/selfreview.md` 的「分鏡審」。
6. 修到沒有 `must`。改了句子就只重查那幾句。然後 `state.py set <id> 旁白`，載入 `narrate`。
